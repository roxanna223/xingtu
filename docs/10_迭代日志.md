> **本文件是项目唯一操作流水账：任何代码/数据/文档改动，必须在当天补记一行。**
> 规则（铁律）：
> 1. 每次改动前先读本日志，了解最近在做什么；
> 2. 改动完成后**当天**在本日志追加一条记录：日期、类型、做了什么、改了哪些文件、是否需要同步其他文档（docs/00~09）；

> 4. 日志只追加不修改历史记录（写错了就新增一条"更正"记录）；
> 5. 每次 git 提交信息应能对应到本日志的一条记录。

### Skill 三标准（v1，注册 / 评测 / 下线）

1. **注册标准**：① 有明确用户价值与触发场景（写进 desc）；② 能用确定性规则路由（rule）或可被 LLM 稳定识别；③ 输出结构化（quiz/result/skill JSON）；④ 先过初心三问（看清了吗/走了吗/尊重人了吗），娱乐类冻结。
2. **评测标准**：① 调度留痕强制——无 skillLog 的 Skill 视为未上线；② 每 Skill 统计触发数/开启数/完成数（后台看板）；③ 结果型 Skill（quiz/goalBreak）以「completed 率」为健康指标，目标 ≥60%；④ badcase 随迭代日志记录，连续同类 badcase ≥3 条必须修 prompt 或路由规则。
3. **下线标准**：连续 2 周触发率 <1% 且 completed=0 → 进观察名单；观察 1 周无回升 → 从 SKILLS 移除 + 日志记录下线原因；红线类问题（危机处理、医疗建议越界）立即下线。
