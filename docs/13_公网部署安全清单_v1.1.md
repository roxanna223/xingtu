## A. 应用层(✅ 已完成 2026-08-25)

### A1 认证重做 ✅
- [x] 密码校验:登录必须比对密码
- [x] 密码哈希:**Node 内置 scrypt + 16 字节随机盐**(`scrypt$salt$hash` 格式),零第三方依赖、跨平台无编译问题;旧 `local-` base64 哈希识别为失效并提示管理员重置
- [x] 登录限流:同 IP 5 次失败锁 15 分钟(进程内 Map,单实例部署足够)
- [x] 注册加固:昵称 2~20 位(中文/字母/数字/`_`/`-`),密码 ≥8 位

### A2 服务端会话 + API 鉴权 ✅
- [x] 会话:HMAC-SHA256 签名 token(`username.exp.sig`,7 天有效),cookie 属性 `HttpOnly + SameSite=Lax + Path=/ + Secure(生产)`
- [x] 签名密钥:`SESSION_SECRET` 环境变量优先;未配置则自动生成持久化到 `data/.session-secret`(0600,已加入 .gitignore)
- [x] 鉴权:全部 13 个 API 路由加 `requireAuth`(仅 `/api/auth`、`/api/status`、`/api/logout` 公开;status 按会话返回,不再泄漏全局状态)
- [x] 登出:清 cookie,不触碰画像数据

### A3 账号模型 ✅(方案 1:单账号演示)
- [x] 注册仅当账号不存在时允许;已有账号时拒绝(409),**杜绝匿名者"注册即清空"数据**
- [x] 忘记密码:管理员 SSH 执行 `node scripts/reset-password.mjs <新密码>`
- [ ] 多用户隔离(方案 2):明确不做,P1 再议

### A4 数据层 ✅(JSON 保留 + 并发安全)
- [x] 原子写:临时文件 + `renameSync`,进程崩溃不产生半截 JSON
- [x] 写锁 `withStoreLock`:`/api/record` 主流程与后台日报链、`/api/report` 全程串行化
- [x] LLM await 后重读:`/api/chat`、`/api/star` 在 LLM 返回后重读 chats/profile 再写回,避免并发丢会话
- [x] SQLite 迁移:维持"不引入"决策(单账号 + 锁已足够,零运维)

### A5 应用安全细节 ✅
- [x] 安全响应头(`next.config.mjs`):CSP、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、Referrer-Policy、Permissions-Policy
- [x] CSRF:全部写 API 校验 Origin 与 Host 一致(跨站 403)
- [x] 输入校验:JSON 体解析限制 200KB + 必须为对象;昵称/密码格式;record 文本截断上限
- [x] 登录页文案:去掉"本地模拟,不会上传",改"只保存在你的星图里"

### A6 密钥管理 ✅(部分需用户操作)
- [x] `.gitignore` 已含 `.env`、`data/*.json`,新增 `data/.session-secret`
- [x] `.env.example` 补 `SESSION_SECRET` 说明
- [ ] ⏳ **DeepSeek/Moonshot Key 轮换**:需用户在 DeepSeek/Moonshot 控制台作废旧 Key 换新(历史上曾泄漏过)
- [ ] ⏳ 服务器 `.env` 需填 `SESSION_SECRET`(部署时生成 64 位随机串)
