## ② 分项目深挖

### 2.1 jrnl — 命令行纯文本日记

- **仓库**：https://github.com/jrnl-org/jrnl （官网 https://jrnl.sh）
- **一句话定位**：不离开终端就能随手记的纯文本日记；「最低摩擦」的命令行形态。

**核心机制 / 架构**
- **数据存储格式**：纯文本文件（默认），每个 journal 一个 `.txt` 文件；条目以日期头分隔，形如 `[2026-08-29 12:34] 内容`；行内用 `@tag` 打标签、`*` 标记星标条目。此外原生支持多种「journal type」：`dayone`（与 Day One App 的 JSON 格式互通）、`json`、`markdown`、`text`——同一引擎可写/导出多种格式。
- **每日条目结构**：无模板、无必填字段；本质是「时间戳 + 一段自由文本 + 可选 @tag / 星标」。
- **编辑器与输入交互**：命令即输入。`jrnl today: 今天下午和小星聊了换工作的事` 一行即完成；`jrnl yesterday`、`jrnl -1` 可补写；`jrnl --edit` 打开默认 `$EDITOR` 编辑；`jrnl -n 5` 回看最近 5 条；`jrnl @工作` 按标签过滤。
- **模板/提示**：无内置引导问题；靠 `--template`（jrnl 支持外部编辑器模板字符串）和 config 里的 `template` 字段做极轻的输入模板。
- **回顾视图**：无图形界面；靠命令行过滤（按日期/标签/星标/关键词）+ 第三方查看器（如 jrnl-viewer、或把文件挂进任意 Markdown/文本工具）。
- **同步与隐私**：本地文件 + 可选的 **AES 加密**（`cryptography` 库，密码加密整个 journal 文件）；多 journal 通过 YAML 配置（`~/.config/jrnl/jrnl.yaml`）管理，天然「每文件即一数据源」。

**与星图「日记」模块的关联点**
- **低摩擦入口**：`jrnl today: ...` 是「一条命令完成一条记录」的极致范本——对应星图 Web 端「主页常驻输入框，回车即存」的 1 次点击/1 次回车目标。→ 借鉴「无标题、无分类、一行即存」。
- **记录内容结构**：时间戳 + 自由文本 + 可选轻标签/星标，正是星图「默认单卡片自由流 + 可选情绪点选」的最小数据模型。→ 可借鉴其「正文不强制结构、元数据后置」。
- **数据可移植与隐私**：纯文本/JSON/Markdown 多格式、单文件可迁移、AES 加密——对星图「导出为用户自有格式」有直接参考价值（至少提供 Markdown 导出）。
- **6:00 日报衔接**：`@tag` 与日期头是天然的可结构化锚点，日报聚合时无需从自由文本强抽标签。
- **编辑器交互 / 回顾视图**：基本无可借鉴（无 GUI）。

**可借鉴资产**：数据格式与「多格式互通」设计（尤其 Day One JSON 互通、Markdown 导出）；配置驱动的多 journal 抽象。技术栈 Python CLI，**不可直接嵌入 Next.js**，但格式定义与交互理念可抄。

**风险**：GPL-3.0（复用代码需开源衍生）；纯 CLI 无 Web 组件；对非技术用户无意义，仅作理念/格式参考。

### 2.2 Mini Diary — 简洁安全的桌面日记（已归档）

- **仓库**：https://github.com/samuelmeuli/mini-diary （官网 https://minidiary.app）
- **一句话定位**：简洁、加密的桌面日记应用；轻字段 + Markdown 正文。

**核心机制 / 架构**
- **数据存储格式**：单个 **JSON 文件**（用户可选存储位置），全部条目序列化在其中；用 **AES-256-GCM** 加密（密码派生，桌面端借系统 keychain/keytar 存密码）。
- **每日条目结构**：每条 entry 含 `id / dateTime / text(Markdown) / mood / weather / location / tags / photos` 等字段——即「一图 + 一句话 + 一组轻字段」。
- **编辑器与输入交互**：Electron + React + TypeScript；单条目编辑器，Markdown 正文；点选 mood（心情图标）、weather、location、tags 等轻字段。
- **模板/提示**：无内置引导问题；靠「字段点选」把结构化输入做轻。
- **回顾视图**：日历导航 + 条目列表 + 全文搜索；导出 JSON / Markdown。
- **同步与隐私**：本地 JSON + 加密；无云同步。

**与星图「日记」模块的关联点**
- **记录内容结构**：`mood/weather/location/tags/photos` 这套「轻字段 + 自由正文」正是星图「可选心情点选（心情色）+ 一张图 + 一句话」的现成字段清单。→ 直接可抄字段命名与粒度。
- **低摩擦入口 / 编辑器交互**：点选字段即结构化，正文可选——印证「输入成本压到 10 秒」。
- **数据可移植与隐私**：单 JSON + 加密 + JSON/Markdown 导出——对星图「导出」格式有参考。
- **每日模板 / 回顾视图 / 6:00 日报衔接**：较弱，仅日历回顾。

**可借鉴资产**：entry 字段模型、加密存储思路。技术栈 Electron/React/TS，**UI 层与 React 同源**（星图是 Next.js React），但已归档、无 Web 版，仅可抄字段设计。

**风险**：**仓库已归档（archived=true，最后推送 2021-07）**，不再维护；仅桌面端，**不可直接嵌入 Web**；依赖已老旧。仅作「字段设计」参考。

### 2.3 RedNotebook — 带日历与标签的桌面日记

- **仓库**：https://github.com/jendrikseipp/rednotebook （官网 https://rednotebook.app）
- **一句话定位**：跨平台桌面日记，日历导航 + 标签 + 模板 + 多格式导出。

**核心机制 / 架构**
- **数据存储格式**：纯文本文件，**每月一个 `YYYY-MM.txt`**，存于 `~/.rednotebook/data/`；条目以 `===== YYYY-MM-DD =====` 标题分隔；行内 `#tag` 打标签。**文件即数据，人可直接读**。
- **每日条目结构**：自由文本正文（支持轻量标记语法 txt2tags）+ `#tag`；无强制字段。
- **编辑器与输入交互**：桌面 GTK 应用；左侧日历选日期即打开当天；编辑器为富文本（基于 txt2tags 标记）。
- **模板/提示**：**内置模板**（`~/.rednotebook/templates/`）——可为每天/周自动插入预设骨架文本（`#date`、`#time` 等占位符）。
- **回顾视图**：**日历视图**（有记的日期高亮/密度示意）+ 标签云 + 全文搜索 + 导航。
- **同步与隐私**：本地纯文本，无云、无内置加密；导出纯文本/HTML/LaTeX/PDF。

**与星图「日记」模块的关联点**
- **回顾视图**：「日历视图 = 复看入口」的最简实现——日历密度（哪天写了）本身就是成就暗示与复看钩子。→ 星图日记可做「月历密度热力图」。
- **每日模板与轻引导**：按天/周自动插入模板骨架，是「轻引导不强制」的旧派实现（模板可留空）。
- **数据可移植**：`YYYY-MM.txt` 每月一文件的组织，纯文本、零锁定。
- **低摩擦入口 / 编辑器 / 6:00 衔接**：较弱（桌面、无结构化字段、无 AI）。

**可借鉴资产**：日历密度视图、每月一文件的纯文本组织、模板占位符。技术栈 Python/GTK 桌面，**不可嵌入 Web**。

**风险**：GPL-2.0+（README 注明因捆绑 LGPLv3 组件，实际按 GPL-3.0+ 分发）；仅桌面；UI 老旧；star 少、社区小。仅作「日历回顾 + 纯文本组织」参考。

### 2.4 Trilium Notes（TriliumNext）— 层级笔记/知识库，脚本化

- **仓库**：https://github.com/TriliumNext/Trilium （原 https://github.com/zadam/trilium ，社区续维护）官网 https://triliumnotes.org
- **一句话定位**：可脚本化的个人知识库；树状笔记 + 属性（标签/关系）+ 内置日历/日记能力 + REST API。

**核心机制 / 架构**
- **数据存储格式**：**SQLite**（`document.db`）存储整棵笔记树；笔记内容存为 **HTML**；「属性（attributes）」是 key-value（`label` 标签 / `relation` 关系），可挂在任意笔记上；笔记可加 `#template`、`#runOnNoteCreation` 等系统标签自动跑脚本。
- **每日条目结构**：内置「日历/日记」机制——给某笔记打 `#calendarRoot` 即成日历根，子笔记按 `#yearNote / #monthNote / #weekNote / #dateNote` 标记日期层级；配 `#template` 让每个新日期笔记自动套模板。
- **编辑器与输入交互**：Electron 桌面 + 自托管 Web；富文本/源码编辑；**JS 脚本化**（前后端皆可跑脚本）实现自动化（自动建当日笔记、自动归档）。
- **模板/提示**：`#template` + `#runOnNoteCreation` + 日期属性 → 「新建当日笔记即套模板」的自动化，是可编程的轻引导。
- **回顾视图**：树导航 + 日历 + 按属性过滤（如按 `#dateNote` 列出全部日记）。
- **同步与隐私**：本地优先，可自托管 sync server；**ETAPI（REST API）** 提供完整的程序化读写（笔记/属性/树），有现成 MCP server 供 LLM 调用。
- **与 AI 结合**：社区有 trilium-fastmcp / mcp-trilium 等，把 ETAPI 暴露给 LLM/Agent（对星图「AI 读日记」的架构有参考意义）。

**与星图「日记」模块的关联点**
- **6:00 日报衔接**：**ETAPI + 属性体系**是「AI 程序化读/写日记内容」的成熟范式——星图日报要「引用日记原话、读日记内容」，可参考其「笔记 + 可查询属性 + REST 读写」的边界设计。
- **每日模板**：`#template + #dateNote + 自动建当日笔记` = 「打开即今日、且自动套轻模板」的完整实现。
- **记录内容结构**：属性(label/relation) 即「结构化元数据后置」——正文自由，结构化靠可挂属性。
- **数据可移植**：SQLite + 导出（markdown/html）导出；树结构比日记重。
- **低摩擦入口 / 编辑器**：树+富文本偏「知识库」，对「轻日记」过重。

**可借鉴资产**：属性体系（label/relation）、ETAPI 的 API 边界设计、模板自动化（runOnNoteCreation）。技术栈 TypeScript/Electron/Node + 自托管 Web，**服务端同为 Node 生态，API 设计可参考**；但整套 UI 是自家框架，不能直接嵌 Next.js。

**风险**：AGPL-3.0（自托管服务若修改需开源）；项目经历作者停更→社区接管（TriliumNext），长期维护存在不确定性；偏知识库，学习成本高；对星图「轻日记」过重。

### 2.5 Logseq — 大纲式 + 内置 Daily Journal（本地优先）

- **仓库**：https://github.com/logseq/logseq （官网 https://logseq.com）
- **一句话定位**：隐私优先的开源大纲笔记；**Daily Journal 是第一公民**（打开即当日日记页）。

**核心机制 / 架构**
- **数据存储格式**：**本地文件夹（graph）里的 Markdown 文件**。日记按天存 `journals/YYYY_MM_DD.md`，普通页存 `pages/*.md`；配置在 `logseq/config.edn`。**块（block）= 一个大纲 bullet（`- ` 开头）**，是引用/嵌入的最小单位。
- **每日条目结构**：一页 = 一串块；块内可用 `属性:: 值`（property，如 `心情:: 平静`）、`#标签`、`[[双向链接]]`、`((块引用))`、`TODO/DOING/DONE`。
- **编辑器与输入交互**：Web/桌面，**outline 编辑**——回车新增兄弟块、Tab 缩进成子块；「今天」页始终在顶部，点开即写；**斜杠命令**、块拖拽、块引用嵌入。
- **模板/提示**：内置 **journal 模板**（`logseq/config.edn` 可配置 `:default-templates {:journals "..."}`，每天自动预填模板内容，含当日日期占位符）；配合 `properties` 做半结构化。
- **回顾视图**：`All Journals` 日历式列表 + **查询（query）**——用 `{{query (property 心情 平静)}}` 之类 Datalog 查询聚合历史块，做「按主题回顾」。
- **同步与隐私**：**local-first**，文件可随意用 Git/网盘同步；内置 Git 自动提交；可自托管。
- **现状**：2024 起官方在开发 **Logseq DB 版（SQLite 后端）**，经典 Markdown 版仍是主流；两者并行。

**与星图「日记」模块的关联点**
- **每日模板与轻引导**：`:default-templates {:journals ...}` 的「**每日打开即带轻模板 + 日期占位**」几乎是星图「今日一问/收束三问可选扶手」的直接模板实现。
- **记录内容结构**：`属性:: 值`（properties）是「半结构化后置」的典范——正文自由写，情绪/主题用 property 一行标记，天然可被 query 和日报消费。→ 星图日记可给「心情色/标签」用同样的「属性后置」表达。
- **编辑器交互**：outline + 块引用 + 反链（backlinks），「块级引用原话」对星图「日报引用日记原话」是极佳范式（块可被 `((块引用))` 精确指到原句）。
- **回顾视图**：query 聚合（按 property/日期/标签回看）→ 星图「日记回顾/日报引用」的可编程聚合思路。
- **数据可移植**：纯 Markdown + Git，零锁定，导出即全套。
- **低摩擦入口**：打开即 Today 页 + 回车即写，摩擦极低。
- **6:00 日报衔接**：块引用 + property + query = 「自由写 + 结构化后置 + 可聚合引用」三位一体，与星图「日报引用日记」高度同构。

**可借鉴资产**：**journal 文件命名（`YYYY_MM_DD.md`）、每日模板、property 后置、块引用/反链、query 聚合**——这些是「日记模块」最值得抄的一组设计。技术栈 Clojure/ClojureScript（**前端复用性差**），但概念/格式可直接移植到 Next.js + 任意存储。

**风险**：AGPL-3.0（直接复用代码需开源；借鉴格式/概念无碍）；正在经历 Markdown→DB 架构切换，方向存在不确定性；outline 心智对部分用户有门槛。

### 2.6 SiYuan 思源笔记 — 块式笔记 + 每日笔记 + AI/Agent

- **仓库**：https://github.com/siyuan-note/siyuan （官网 https://b3log.org/siyuan）
- **一句话定位**：隐私优先、自托管的「块式」知识空间，内置**每日笔记（dailynote）**与 AI/Agent 能力。

**核心机制 / 架构**
- **数据存储格式**：**块（block）= 最小单元**，每个块是一个 JSON 对象（`id / type / content / children / ial(行内属性) / updated` 等），文档由块树组成；本地存为 **JSON（`.sy` 文档树文件）+ `assets/` 附件目录**，本地优先。
- **每日条目结构**：内置**每日笔记**——按文档路径 `/daily note/YYYY/MM/DD` 自动建档，`dailynote` 模板（设置里可配，默认模板含日期/待办等块）决定初始结构。
- **编辑器与输入交互**：桌面 + Web + 移动 + 自托管；块编辑器（块级拖拽/折叠/反链/块引用 `((id "锚文本"))`）；斜杠命令；支持 S3/WebDAV/官方云同步。
- **模板/提示**：dailynote 模板 + 任意模板片段；反链面板。
- **回顾视图**：文档树 + 日记信息流视图 + 反链 + 全文搜索；块引用把原句嵌入别处。
- **同步与隐私**：**本地优先**，自托管；数据完全 JSON 可解析；**内置本地 HTTP 内核 API（默认 127.0.0.1:6806）**，近期加入 **MCP / Agentic AI**（"humans and AI agents work together"）——AI 可通过 API 读/写/整理块。
- **与 AI 结合**：官方定位已转向「人与 AI agent 协作的知识空间」，API + MCP + AI 写作整理是当前主线。

**与星图「日记」模块的关联点**
- **记录内容结构 + 6:00 日报衔接**：**块级 JSON + 块引用**是最适合「日报引用日记原话」的存储形态——每条日记是一个可被唯一 ID 引用的块，AI 日报可精确嵌入原句；思源的「AI 读块/写块」正是星图要做的「AI 读日记→归纳」的成熟参考。
- **每日模板**：`dailynote` 路径 + 模板 = 「每日归档 + 自动建档 + 轻模板」的完整范式。
- **编辑器交互**：块编辑器（拖拽/折叠/引用）体验好，但**实现重**（星图不必复刻）。
- **数据可移植**：JSON + 附件 + 多同步后端；本地优先。
- **低摩擦入口 / 回顾视图**：入口偏「知识库」；回顾靠反链/搜索/信息流。

**可借鉴资产**：块 JSON schema（`id/type/content/children/ial`）、dailynote 模板、块引用、**内核 API + MCP 的「AI 可读写知识库」边界设计**。技术栈 TypeScript（前端 + 内核，**与星图 React 生态同语言**，但编辑器是自研、不可直接内嵌；API/MCP 设计最值得参考）。

**风险**：AGPL-3.0；功能庞大、与「轻日记」定位比过重；块编辑器复杂度高；中文社区强但文档/国际化对非中文团队有成本。

### 2.8 SilverBullet — 自托管 Markdown + Lua 脚本（可嵌入性最佳候选之一）

- **回顾视图**：`#query`（查询语言）+ 页面索引（index page）聚合；日历/Library 视图靠 Plug 扩展。
- **同步与隐私**：本地文件 + 自托管；单用户为主，**MIT 许可**。
- **可嵌入性**：Web 单页应用（TypeScript/Deno），前端是自家轻量组件。

**与星图「日记」模块的关联点**
- **可嵌入 Web 的组件**：SilverBullet 是候选里**最接近「可借鉴/嵌入 Web」的轻量 Markdown 编辑器**（MIT、TS、浏览器原生），其斜杠命令 + 模板 + frontmatter 的「轻编辑器」范式可作星图日记编辑器的蓝本。

- **记录内容结构**：frontmatter 属性后置 + 纯 Markdown 正文。

**可借鉴资产**：**编辑器 + 斜杠命令 + Page Template + frontmatter 属性**这套轻量组合；Space Script/Lua 是「用户可编程自动化」。技术栈 TypeScript/Deno，**MIT 许可、最宽松，前端组件范式可直接借鉴**（非直接 import，但思路/交互可复刻）。

**风险**：单用户/自托管为主，多用户不是重点；社区中等（5.9k star）；Lua 脚本门槛对普通用户略高（但星图不必暴露）。

### 2.9 ActivityWatch — 开源自我量化（自动追踪时间/应用使用）

- **仓库**：https://github.com/ActivityWatch/activitywatch （官网 https://activitywatch.net）
- **一句话定位**：开源自动化时间追踪器；把「你在设备上做了什么」自动记录成可查询的事件流。

**核心机制 / 架构**
- **数据存储格式**：**bucket/event 模型**——每个数据源一个 **bucket**（存为本地 JSON 文件，newline-delimited JSON）；每条 **event** = `{timestamp, duration, data: {...}}`。**极简、通用、可无限扩展**。
- **每日条目结构**：无「日记」；事件流天然带时间戳，`data` 里放源专属字段（如窗口标题、URL、App 名）。
- **编辑器与输入交互**：**无手动输入**——watcher（监视器）后台自动采集（窗口/AFK/浏览器等），用户零摩擦；「追踪是自动的，不是手动的」。
- **模板/提示**：无。
- **回顾视图**：本地 **Web Dashboard**（时间线、分类统计、活动可视化）+ **REST API**（`aw-server` 提供 `GET /api/0/buckets/.../events` 等）。
- **同步与隐私**：**local-first、隐私优先**，数据不出本机；Python 后端 + Web 前端；MPL-2.0。

**与星图「日记」模块的关联点**
- **数据模型（最重要借鉴）**：`bucket + event{timestamp, duration, data}` 是「**把一切记录统一成带时间戳的事件流**」的干净范式。星图手里有**日记、AI 对话、情绪点选、星图节点**多种记录——用「事件流」统一建模后，6:00 日报只需「按时间窗聚合事件」即可，天然支持多源。→ 强借鉴。
- **低摩擦入口**：自动采集 = 摩擦趋零的极端——启示：星图可用**已有行为数据（对话、情绪、浏览过的节点）当「锚点素材」**（呼应 17 号文档的 Apple Journal「建议时刻」），把「想记」变成「对已有素材补一句」。
- **回顾视图**：时间线 + 分类统计 Dashboard——星图日报/周报可视化的参考。
- **6:00 日报衔接**：事件流 + REST 聚合 = 日报引擎的数据管道范式。
- **记录内容结构 / 编辑器 / 模板**：不涉及（无手动输入）。

**可借鉴资产**：**bucket/event 数据模型 + REST API + 本地 Dashboard**。技术栈 Python 后端 + Web 前端；**前端不复杂，概念可移植**；但整体是独立本地服务，不可直接嵌 Next.js。

**风险**：MPL-2.0（文件级 copyleft，宽松）；它是「自动量化」而非「手动日记」，方向不同，仅借数据模型/可视化；多用户/云端非其重点。

- **编辑器与输入交互**：侧边栏标注/高亮/写笔记；**Memex 2.0 加 AI 对话**（对已存内容问答）。
- **模板/提示**：无。
- **回顾视图**：时间线 + 全文搜索 + 集合（spaces）聚合。
- **同步与隐私**：本地优先（历史不传云）；扩展形态（Chrome/Firefox）。

**与星图「日记」模块的关联点**
- **低摩擦入口（「素材反推」的最佳工程范本）**：Memex **自动捕获用户「看过什么」**并做成可检索、可标注的素材库——正是星图「用已有行为数据当日记锚点」的技术印证：日记入口旁可列出「今天看过/聊过/记录过的素材」，点一下即以它为锚开写（呼应 Apple Journal「建议时刻」）。
- **回顾视图**：全文检索 + 时间线。
- **数据可移植 / 隐私**：本地优先，但**无云/无多用户**。
- **6:00 日报衔接**：AI 对本地内容的问答是「AI 读个人历史」的先例。
- **记录内容结构 / 编辑器 / 模板**：弱。

**可借鉴资产**：**自动捕获 → 本地索引 → 可检索/可 AI 问答**的「素材管道」设计；全文检索体验。技术栈 TypeScript（浏览器扩展），**前端同语言，但形态是扩展、不可直接嵌 Web 应用**。

**风险**：**License 未声明（GitHub API license=null）** → **不可复用其代码**，只能借鉴理念；近年方向摇摆（Memex 2.0 转向 AI，社区活跃度一般）；浏览器扩展非服务端多用户模型。

## ④ 对星图「日记」模块的可借鉴结论（按模块分组 + 优先级）

> 优先级说明：P0 = 强烈建议本轮就吸收；P1 = 建议吸收；P2 = 视投入可选。

### 4.1 数据存储格式（决定可移植性与可摘要性）

- **【P0】日记正文用自由文本（Markdown 或纯文本），结构化用「属性后置」而非前置强制** —— 来自 Logseq（`心情:: 平静` property）、SiYuan（块 `ial` 属性）、SilverBullet（frontmatter）。正文永远自由写，情绪/主题等作为可选属性挂在条目上。这样既保「自由写作」，又让 6:00 日报能直接消费结构化字段。
- **【P0】每日一实体、按自然日归档** —— 来自 Logseq `journals/YYYY_MM_DD.md`、RedNotebook `YYYY-MM.txt`、SiYuan `/daily note/YYYY/MM/DD`。星图日记应「每天一个条目（或一份文档）」，与日报 6:00 边界（过去一整天）对齐。
- **【P0】「事件流」作为底层统一模型** —— 来自 ActivityWatch `bucket/event{timestamp,duration,data}`。星图已有日记、AI 对话、情绪点选、星图节点多类记录，可用「带时间戳的事件流」统一，日报 = 按时间窗聚合事件。这是「日记与对话一起归纳」的最干净底座。
- **【P1】提供 Markdown / JSON / SQLite 导出** —— 来自 jrnl（多格式互通）、Dogsheep（SQLite 可查询）。星图「数据可移植/隐私」卖点应有「一键导出为 Markdown 或 SQLite」。
- **【P2】块级 ID + 块引用** —— 来自 Logseq `((块引用))`、SiYuan 块 JSON。若要让「日报引用日记原话」精确到句，需条目下更细的「块/段落 ID」。可先不做（用段落锚文本代替），进阶再上。

### 4.2 低摩擦入口

- **【P0】主页常驻输入框 + 打开即今日 + 回车即存** —— 来自 jrnl（`jrnl today: ...` 一行）、Logseq/SilverBullet（打开即 Today 页）。对应 17 号文档「1 次点击 / 1 次回车」目标。无标题、无日期选择、无必填。
- **【P0】用已有行为数据当「锚点素材」反推记录** —— 来自 ActivityWatch（自动采集事件流）与 Memex（自动捕获→可标注）的工程印证 + 17 号文档 Apple Journal「建议时刻」。日记入口旁放「昨天/今天与小星聊到的事」「今天记录过的情绪/节点」可点锚点，点了即以它为起笔。
- **【P1】一键打卡/点选把最低成本压到 10 秒** —— 来自 Loop Habit（一键打卡）、Mini Diary（mood 点选）。星图「心情色点选 + 一句话」已在此列。

### 4.3 编辑器交互

- **【P1】斜杠命令 + 轻 Markdown 编辑器** —— 来自 SilverBullet（MIT、TS、浏览器原生）。星图日记编辑器宜走「轻 Markdown + 斜杠命令（插入情绪/模板/待办）」路线，而非 Logseq/SiYuan 的重型块编辑器。SilverBullet 是候选里**唯一「MIT + 浏览器原生 + 轻量」的可直接对标编辑器**。
- **【P2】outline/块编辑** —— 来自 Logseq。仅当星图要做「条目内更细的结构化」时再考虑，当前偏重、可缓。

### 4.4 每日模板与轻引导

- **【P0】「每日模板 = 可删除的轻骨架」而非必填表格** —— 来自 Logseq `:default-templates {:journals ...}`（打开即带模板+日期占位）、SilverBullet Page Template（按页面类型自动套、可删）、RedNotebook 每日模板。星图把已有「收束三问」做成**可删/可跳过的日记末尾轻骨架**。
- **【P1】「今日一问」可选问题** —— 对齐 17 号文档 Day One/Apple Journal 模式；开源侧 RedNotebook/Logseq 模板可承载「每天一个问题占位」。
- **【P1】Habitica `Dailies` 语义（每日出现、不强制、无惩罚）** —— 借鉴「每天有个『今日』锚点，写了没写都不惩罚」，与星图「不强制」一致；但**拒绝其扣血/失败惩罚**（与星图调性冲突）。

### 4.5 回顾视图

- **【P0】月历密度热力图 + 轻 Streak（正面化）** —— 来自 RedNotebook 日历密度、Loop Habit 日历热力图+Streak。星图日记可做「本月写了 N 天」正面展示，**不搞断更负罪**。
- **【P1】「那年今日 / On This Day」** —— 对齐 17 号文档；开源侧 RedNotebook/Logseq 的按日期回看是其朴素实现。
- **【P1】按属性聚合回顾（query）** —— 来自 Logseq query、SiYuan 反链/搜索。星图可做「按情绪/主题回看我的日记」。
- **【P2】数据可视化 Dashboard** —— 来自 ActivityWatch 时间线/统计、Datasette 图表。星图日报/周报可视化可参考。

### 4.6 数据可移植与隐私

- **【P0】本地优先/自持 + 可导出** —— 几乎所有候选都是 local-first；星图虽是服务端多用户，但应保证「用户可随时导出全部日记 + 数据可删除」。Logseq（Markdown+Git）、SilverBullet（纯 Markdown）、Dogsheep（SQLite）给出三种可移植出口。
- **【P1】加密** —— Mini Diary（AES-256-GCM 单文件加密）、jrnl（AES 加密 journal）是「端到端/静态加密」参考；星图如要「隐私」卖点可参考其加密粒度（但多用户服务端加密另有复杂度，需单独评估）。

### 4.7 6:00 日报衔接（AI 读日记）

- **【P0】AI 程序化读/写日记的 API 边界** —— 来自 Trilium ETAPI、SiYuan 内核 API+MCP（「人与 AI agent 协作」）。星图日报要「读日记→归纳→引用原话」，应把日记做成**带 ID、可被程序精确读写的资源**（而非纯自由字符串），这是「AI 可摘要性」的前提。
- **【P0】结构化字段直接喂日报，自由文本交给现有抽取** —— 情绪点选、可选标签、今日一问作答 = 结构化锚点；正文 = 抽取提示词处理（Logseq property / SiYuan ial / SilverBullet frontmatter 证明「自由写 + 属性后置 + 可聚合」可行）。
- **【P1】引用原话到「块/段落」粒度** —— 来自 Logseq 块引用、SiYuan 块引用。日报「引用日记原话」应尽量精确到句/段。

### 4.8 一句话结论

> 星图日记的数据层参考 **Logseq 的「每日一文件 + 属性后置 + 每日模板」**，底层用 **ActivityWatch 的「事件流」** 统一日记/对话/情绪，编辑器对标 **SilverBullet 的「轻 Markdown + 斜杠命令 + Page Template」（MIT、最可复用）**，AI 读写边界参考 **Trilium ETAPI / SiYuan 内核 API+MCP**；入口做「常驻输入框 + 已有素材锚点」，回顾做「月历密度 + 那年今日 + 按情绪聚合」，并保证 Markdown/SQLite 可导出。
