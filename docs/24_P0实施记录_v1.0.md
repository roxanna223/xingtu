## 2. 关键设计决策（与方案文档的对应）

1. **日记与旧记录管线并存**：日记保存时镜像写 days 表（q2=情绪点选轨迹），周期报告/历史清单零改动继续可用；抽取管线复用 `extractAndMerge`。
2. **引导会话复用 star 会话**：guide 标志由客户端逐条消息携带（刷新后引导状态重置为普通聊天，梳理卡从最后一条带 draft 的助手消息恢复）。
3. **进化观察时机**：每条非控制消息回复后触发一次后台抽取（约 8 轮窗口），与"6:00 日报同批反思"的完整版相比是 P0 的轻量替代；完整版 sleep-time compute 留 P1。
4. **个人资产边界**：persona 三文档 + persona_meta 均随账户级联删除（ON DELETE CASCADE）；查看/导出/删除 UI 留 P1（数据层已具备）。

## 4. 验证方式

1. `npm run build` 通过（v7 迁移自动执行）；
2. 登录 → 首页见「和小星聊聊 / 写日记」两大入口，NavBar「日记」tab；
3. /diary：点情绪、写一句话（回车写入）、自由书写自动保存；刷新后内容保留；
4. /chat：空界面第 1 张卡片进入记录引导 → 聊几句 → 「✨ 帮我梳理」→ 编辑梳理卡 → 「📖 存进日记」→ /diary 可见；
5. /report：日报出现「我的坐标 · 目标/自我/差距」与「成长规划」区块；
6. 反馈「没帮助」/采纳「已做到」后，进化层条目置信度变化（数据层 `persona_meta`）。
