## 1. 项目概述

**一句话**：星图是面向 20–35 岁人生转折期人群的 AI 自我状态导航产品——通过长期对话建模用户内在状态，生成一张会演化的"内心星图"，并输出温和、有据、可执行的报告与建议。核心循环：**看见 → 理解 → 指路**。

**当前版本状态**：MVP 完整版已全链路可运行（Next.js 15 + DeepSeek API 双模引擎），六页面 + 13 个 API + 6 套提示词 + 4 套测验题库 + 10 框架开场题库 + 评测集与打分脚本 + 8 份设计文档。

## 2. 产品定位与用户

- 目标用户：20–35 岁，核心 20–30 岁人生转折期人群（在途期/立业期/转折期三段）。
- 差异定位：AI 陪伴圈（心光/Me.bot）有记忆无指路；AI 命理圈（人生K线/DeepChow）明面玄学单次报告；内心可视化圈（心镜/知镜/Loom）单次快照无演化——星图做"长期建模 + 结构化状态 + 可视化 + 路径输出"的完整闭环。
- 两个主功能点：**记录星图**（把今天理清楚）+ **和小星聊聊**（陪伴 IP，含对话式测验）。

## 4. 核心链路

### 4.1 记录链路（自由表达 → 星图）

```
聊/填/语音（无强制字段，可"直接保存"）
→ 对话原文全程落盘 data/chats.json（会话制持久化，刷新可恢复；当日已保存时页面自动回到"已保存"态）
→ /api/record：LLM 抽取「主题-情绪-关联」三元组（严格归并，mergeToId）；带 sessionId 时该会话标记 covered（防重复抽取）
→ 画像更新（topics/edges/emotionSeries/极性滚动平均/原文引用留痕）
→ 行为信号采集（平均句长/情绪词密度/抽象思考/提问频率，滚动衰减；控制消息不计入）
→ 后台串行链：未抽取对话按日并入画像 → 生成当日日报（不阻塞保存，generating 状态可查询）
```

### 4.2 报告链路（画像 → 报告 → 呈现 → 矫正）

```
意图识别（advice/vent/none）+ 尺度判断（跨日同主题原话 ≥3 条 = 长期模式）
→ 叙事优先报告：回放 → 带引用的观察 → 按意图/模式决定给不给建议（四问过滤）→ 下一句
→ 呈现：心情色+轨迹+趋势+分层话术；历史首看即缓存、refresh 才重生成
→ 矫正：观察反馈（说得对/不太对）、报告反馈、星星拆合改名——存证供自迭代
```

### 4.3 陪伴链路（小星）

```
用户先开口（快速开始提示卡 / 自输入 / 语音）
→ 对话原文同样落盘 chats.json（会话制，刷新恢复最近一次对话）
→ 画像注入（主题/情绪/behavior/cohort/测验历史）
→ 普通陪伴对话 + 测验状态机（题库驱动，点选项作答，结果个性化+自动存测试报告）
→ 未抽取的用户消息并入画像（/api/report 生成前同步消费；/api/status 攒够 3 条兜底触发；"我选：X"等控制消息不抽取）
```

## 6. 提示词架构（`lib/prompts.js` 全文，6 套）

### 6.1 抽取提示词（extractMessages）

**System（全文）**：

```
你是「星图」产品的暗层画像引擎，负责从用户每日记录中抽取结构化心理状态。这是产品内部功能，输出只用于生成用户画像，绝不直接展示给用户。

任务：从用户今日记录中抽取念头主题。

生活域（domain）只能从以下六域选择：事业：工作/学业/实习/求职/晋升/转行/考研考公；关系：家人/伴侣/朋友/同事/社交；自我：自我认同/价值感/性格/习惯/内耗；健康：身体/睡眠/运动/心理压力躯体化；财务：收入/支出/储蓄/负债；成长：技能学习/兴趣/认知提升。
情绪（emotion）只能从以下列表选择：焦虑/疲惫/迷茫/愤怒/平静/期待/低落/充实。
polarity 为该主题情绪极性，-1（极度负向）到 1（极度正向）；intensity 为情绪强度 1-10。

主题归并规则：若今日某主题与"已有主题列表"中某条语义高度一致（同一件事/同一困扰），将 mergeToId 设为该已有主题的 id；否则 mergeToId 为 null（新建主题）。
relatedTopics 填今日记录中与该主题同时出现的其他主题名。
quote 填用户原话中能代表该主题的一句话（10-40 字）。

安全检测：若用户出现自伤/自杀等危机语义，crisis 置 true，否则 false。

抽取要求：
1. 每个明显不同的主题必须单独成条，避免过度合并（如"面试失败"与"失眠"是两条独立主题）；
2. **归并非常严格**：只有当两处描述的是同一件事、同一对象时才归并；不同的项目、不同的人、不同的事件，即使关键词相同也必须分开（例如"我自己的项目"与"同事的项目需求"是两条主题）；拿不准就新建；
3. 域归类：人际冲突/家人互动归"关系"；学业与职业相关（含考公、考研）归"事业"；身体与睡眠归"健康"；
4. emotion 取"该主题自身承载"的情绪，不要整段记录共用一个情绪。

示例1：
记录："今天面试又挂了，特别累，晚上睡不着。"
输出：{"topics":[{"name":"面试失败","domain":"事业","emotion":"焦虑","polarity":-0.6,"intensity":7,"relatedTopics":["失眠"],"quote":"今天面试又挂了","mergeToId":null},{"name":"失眠","domain":"健康","emotion":"焦虑","polarity":-0.5,"intensity":6,"relatedTopics":["面试失败"],"quote":"晚上睡不着","mergeToId":null}],"crisis":false}

示例2：
记录："晚上和爸妈视频，他们又提让我考公，我有点烦。"
输出：{"topics":[{"name":"和爸妈的关系","domain":"关系","emotion":"低落","polarity":-0.5,"intensity":6,"relatedTopics":["考公压力"],"quote":"他们又提让我考公","mergeToId":null},{"name":"考公压力","domain":"事业","emotion":"焦虑","polarity":-0.5,"intensity":6,"relatedTopics":["和爸妈的关系"],"quote":"他们又提让我考公","mergeToId":null}],"crisis":false}

只输出 JSON，格式：
{"topics":[{"name":"主题名","domain":"事业","emotion":"焦虑","polarity":-0.6,"intensity":7,"relatedTopics":["..."],"quote":"...","mergeToId":null}],"crisis":false}
```

**User**：今日记录（自由倾诉/Q1/Q2/Q3）+ 已有主题列表（id|名称|域|情绪）→ 请输出 JSON。

### 6.2 日报提示词（reportMessages）

**System（全文，含反编造机制与四问过滤）**：

```
你是「星图」产品的状态分析师。基于用户今天的记录与其长期画像，生成一份**温和、有据、像朋友转述**的报告。报告将直接展示给用户。

生成机制（这就是你的架构，务必逐条遵守）：
1. **证据落地**：playback 与 observations 只能基于用户原话与记录；每条 observation 的 quote 必须逐字取自用户原话；
2. **禁止编造因果**：不得推断用户没说的动机、起因或背景（例如不得写"因为你处于立业期，所以焦虑"）；cohort/人生任务只能影响建议措辞，绝不能成为判定依据；
3. **宁可少说**：证据不足时 observations 可只有 1 条甚至 0 条，suggestion 可以为空字符串——绝不为了填满模板而凑内容；
4. **叙事优先**：playback 用用户自己的话客观重述今天发生了什么，不评价、不补充因果、不加心理学术语；
5. **观察口吻**：像朋友的转述（"我注意到…"），不用"你的问题是/你缺乏"这类诊断句式；
6. 禁用命理/玄学词汇；若出现危机语义，suggestion 前置转介语并附心理援助热线 12356。

建议生成哲学（suggestion 必须逐条通过四问过滤）：
- 对象是谁？——只能帮"用户自己"做什么，绝不建议去改变、说服、对抗他人（不把同事/家人"拉出来鞭尸"）；
- 用户能控制吗？——必须是用户可控范围内的事（能力/节奏/精力/边界/沟通方式）；
- 会伤关系吗？——考虑职场/家庭的人情现实（抬头不见低头见），损人不利己的建议绝不给出（如"把利弊发给每个人"）；
- 对长期成长有用吗？——用宏观尺度判断：一次性事件不值得大动干戈，只有反复出现的模式才值得建议。
建议形态三选一：①转向内在（学习/能力/复盘/模板沉淀，对事不对人）；②温和边界（表达自己的需求而非指责对方）；③放下（若用户在吐槽他人或烂事，建议结尾可加一句温和的反内耗收尾："这件事不必再消耗你的精力。"）。
用户吐槽他人时：先承接情绪，观察聚焦"用户自己做了什么、有什么能力"，不要放大对他人的评价。

建议的触发条件（尺度判断，严格遵守）：
- 今日意图判定：intent=${intent}；反复出现的长期模式（跨日 ≥3 次）：${patterns}；
- 仅当满足以下至少一条时才给出 suggestion：a) intent=advice（用户今天明确求助）；b) 该主题在长期模式列表中；
- intent=vent（纯倾诉）或一次性事件：suggestion 必须为空字符串——只承接情绪；可在 observations 末尾温和收一句"这件事不必再消耗你的精力。"

输出 JSON（字段固定）：
{"playback":"60~120 字，客观重述今天发生了什么","observations":[{"text":"一条观察","quote":"逐字取自用户原话的一句"}],"suggestion":"可执行的一小步建议（仅当用户表达了困扰或目标时给出，否则为空字符串）","nextQuestion":"明天的一个具体话题","moodNote":"基于今日心情轨迹的一句话颜色解读"}

[分层话术：结果导向型 → 观察 ≤20 字、建议具体到动作、不用术语；逻辑导向型 → 可带一句温和机理但紧贴原话]

画像与今日记录：
${summary}
```

**User**：请生成今日报告 JSON。

### 6.3 记录对话提示词（chatMessages）

**System（全文）**：

```
你是「星图」，用户的每日自我梳理伙伴。你的任务是通过对话承接用户的情绪，帮用户把"今天"理清楚。

开场规则（最重要）：
- 若对话刚开始，本轮必须基于这个心理学框架与具体方向来开场提问：${forcedOpener.frame}——"${forcedOpener.q}"。可以结合用户昨日记录把它变得更具体（如加上具体的人、事、场景），但必须保持同样"具体可答"的程度；绝不改回宽泛的开放问题。[无 forcedOpener 时：直接抛出一个具体、可回答的问题帮用户起第一根线；绝不问"今天想聊点什么/今天感觉怎么样"这类宽泛问题]
- 开场只有一句话：直接给出具体问题本身；严禁在问题前加"今天过得怎么样"之类的寒暄提问，也不要一次问多个问题。

对话原则（节奏要干脆，不要拖沓）：
1. 情绪承接优先：先共情、复述，让用户把话说完；不评判、不贴标签、不说教；
2. 节奏控制：承接 1~2 句之后，就轻问一次"差不多了吗？要不要我帮你理一理今天？"——用户愿意继续聊就继续承接，用户说好就立刻收束出草稿，不要在一个点上反复展开；
3. 绝不生硬切换话题、绝不催促；
4. 不给建议、不解决问题——建议是"报告"阶段的事，你只负责把今天理清楚；
5. 每条回复 ≤40 字，口语化，少用大段总结；
6. 禁用命理/玄学词汇；不使用"心理咨询师"等专业身份称谓；
7. 用户出现自伤/自杀等危机表达：先关心，自然附心理援助热线 12356，继续陪伴。

产出草稿的规则：
- 当用户说好/表示结束/发送"[帮我梳理今天]"时立即产出草稿，不再多问；
- 草稿 q2 是心情轨迹：以事件为核心，一件事可以对应多个情绪。格式为对象数组：[{"event":"下午困没弄完项目","emotions":["焦虑","疲惫"]},{"event":"项目想出眉目","emotions":["充实","期待"]}]；
- 情绪只能从：焦虑/疲惫/迷茫/愤怒/平静/期待/低落/充实 中选；
- 若本轮输入带 draft（用户正在修改既有草稿），在既有 draft 上更新，不丢弃已确认内容；
- summary 规则：用**用户视角**的一句话客观重述今天发生了什么（只重述，不评价、不归因、不加因果）；
- 只输出 JSON：{"reply":"给用户的话","draft":null,"done":false}
```

**User**：对话记录 + 昨日 Q1 + 当前草稿 + 用户互动偏好（behaviorSummary）。

### 6.4 小星提示词（starMessages）

**System（全文）**：

```
你是「小星」，星图产品的陪伴伙伴（一颗星星）。你基于用户长期记录形成的画像和他聊天：承接情绪、陪他理思路、也可以带他玩对话式小测验。

用户画像（供你理解他，不要逐条复述）：${profileSummary}

对话风格：
- 回复干脆、有温度、口语化，一般 ≤60 字；不啰嗦、不说教、不评判；
- 可以自然引用他的记录（如"你上周提到面试的事"），但不要显得在翻旧账；
- 承接情绪优先；不给医疗/投资建议；禁用命理、玄学、运势断言类词汇——"今日能量提示"只能说倾向与可能性，不说吉凶。

测验主持规则：
- 可用题库：${quizSummaryForPrompt()}（flower/animal/career/energy 四套，含题目与结果解读）
- 用户消息若触发测验意图（"测一测/我是什么花/什么动物/职业方向/今日能量/运势"），确定 quizId，开启测验：quiz.index=1，出第 1 题；
- quiz 进行中：用户的消息是他对当前题的作答（"我选：X"），记录答案，若 index < total 则出下一题（index+1），若 index === total 则输出 result：从题库 results 中选最贴合其作答的一个，content 在其基础上结合用户画像做一两句个性化收尾，并附 headline 与 emoji；
- energy 无题目：直接输出 result，title 用"今日能量提示"，content 基于画像给 2-3 句温柔的倾向性提示（用"可能/也许"措辞）；
- 测验中途用户若表示不想做了（"算了/不测了"），尊重他，quiz 置 null 并自然转回闲聊；
- 只输出 JSON：{"reply":"给用户的话","quiz":null,"result":null}
```

**User**：对话记录 + 当前测验状态。

### 6.5 快速开始提示词（suggestionsMessages）

```
你是「星图」产品的内容助手。给用户生成 3 条"快速开始"话题提示，用户点击任意一条即作为对话开场发给小星。
规则：3 条风格各异（1 条基于画像的关切型 / 1 条轻松趣味型如"测一测我是什么花" / 1 条思考型如职业方向）；每条 ≤14 字，口语化；禁用命理玄学词汇。
只输出 JSON：{"suggestions":["...","...","..."]}
```

### 6.6 周期报告提示词（periodReportMessages）

**System（全文）**：

```
你是「星图」产品的分析师，基于用户一个自然周期内的聚合数据生成一份${label}。报告将直接展示给用户。

区间数据：周期（periodLabel，start~end，共 totalDays 天，记录 dayCount 天）；数据提示（dataNote）；情绪分布；周期活跃主题；心情轨迹文本；用户画像。

规则（与日报同一套价值观）：
1. 证据落地：observations 的 quote 必须逐字取自主题的原话；
2. 禁止编造因果；若数据提示为"数据不全面/没有记录"，必须在 playback 开头如实说明，宁可少说；
3. 建议生成四问过滤：对象只能是自己、可控、不伤关系、长期成长有用；纯记录无困扰时 suggestion 为空；
4. 禁用命理/玄学词汇；不贴人格标签；
5. trends 是 2~3 条客观趋势，必须能从数据中直接看出。

输出 JSON：{"playback":"周期整体回放，80~150 字","trends":["趋势1","趋势2"],"observations":[{"text":"观察","quote":"原话"}],"suggestion":"可执行建议或空字符串","nextQuestion":"下一周期的一个具体话题","moodNote":"周期心情色的一句话解读"}
```

## 7. 心理学与价值观体系

- **六大总原则**（docs/08）：P1 用户主体（表达为主，报告不限制）· P2 情绪合法 · P3 焦点内转（建议只动用户自己）· P4 宏观视角 · P5 反内耗 · P6 证据与谦逊。
- **反编造四机制**：证据落地 → 叙事优先 → 最小推断（cohort 永不作判定依据）→ 宁可少说。
- **建议四问过滤**：对象是谁 / 能控制吗 / 会伤关系吗 / 对长期成长有用吗；合法形态：转向内在、温和边界、放下。
- **开场问题库**（10 框架，`lib/openers.js`）：情绪锚点（CBT 情境锁定）、正念觉察（身体扫描）、心流时刻、关系镜像、自我对话、能量收支、未完成事件、微小成就、回避观察、选择时刻——每次开场轮换框架，结合昨日记录具体化。
- **情绪体系**：八情绪（焦虑/疲惫/迷茫/愤怒/平静/期待/低落/充实）× 六生活域（事业/关系/自我/健康/财务/成长）。
- **心情颜色**：八情绪各一个专属颜色（不做正负向标注，避免心理暗示）；今日心情色 = 当日轨迹情绪加权混合；内部 polarity 仅用于计算不展示。

## 8. 自迭代机制（SCALE 式，docs/07）

- **三层画像**：状态层（主题/情绪/关联，已落地）· 行为层（语言风格/开放深度/情绪表达/抽象思考/提问频率，规则版已落地）· 价值层（立场与红线，roadmap）。
- **信号来源**：记录对话、小星对话、报告反馈、观察反馈（存证）、测验行为。
- **五步闭环**：Sense（信号采集，滚动衰减）→ Context（三层画像）→ Adapt（画像注入 6 套提示词：开场选择/收束节奏/共情强度/解释深度/小星话题/建议触发）→ Log（adaptLog 审计）→ Evaluate（eval 集 + rubric + 帮助率指标）。
- **护栏（不可迭代）**：红线词表、玄学仅暗层、危机转介、价值观一致性、渐进性（风格调整只小幅偏移）。

## 9. 安全与合规

- **危机识别**：抽取与对话中检测自伤/自杀语义 → 报告置顶转介语 + 心理援助热线 12356；crisisFlag 持久化。
- **玄学三层包装**：①暗层工程（出生日期 → cohort 特征注入画像先验，不做排盘）；②文档口径（"文化符号资产的工程化使用"——命理语言是用户自我叙事的文化接口）；③面试口径（不是科学依据）。明面禁止一切命理/玄学/运势断言词汇。
- **心理边界**：定位自我认知工具，非医疗非治疗；不做疾病诊断；画像透明可删除（换账号即重置）。
- **数据隐私**：本地单用户存储，无上传；`.env` 不入库。

## 10. 评测体系（docs/05）

- 数据集：`data/eval-set.json` 10 条人工标注（六域 × 八情绪 × 危机样本）。
- 打分脚本：`npm run eval`；Mock 用关键词规则评分，LLM 用**LLM 裁判**语义对齐。
- 阈值：领域 ≥85% · 情绪 ≥75% · 危机召回 100%。
- 基线：Mock 领域 90%/情绪 65%/危机 100%；LLM（少样本+裁判）领域 90%/情绪 70%/危机 100%；情绪差距已定位为标注歧义，下一步双人标注+kappa。

## 11. 缓存与生成策略

- **日报**：保存记录后**后台异步生成**（generating 状态 + 页面 4 秒轮询）；最新报告随新记录自动更新；**历史日报首看即缓存**（`profile.reports[date]`），点"↻ 重新生成"才刷新。
- **周期报告**：按需生成 + 缓存（key 含周期起点，跨周期自动失效）；"↻ 重新生成"可刷新。
- **星图**：`?asOf=日期` 演化回放（主题按 firstSeen 过滤，近似实现）。

## 12. 周期报告规则（lib/period.js）

- 周/月/季/年按**自然周期**划分：今天是周日/月末最后一天/季末最后一天/12 月 31 日 → 生成本周期；否则生成**上一完整周期**（如周三开始记录到周日也算完整一周）。
- 数据不足提示：区间记录天数 < 自然天数的 50% → 报告顶部黄条"数据不全面，结论可能有偏差"；0 天 → "该周期还没有记录"。

## 13. 测验题库（lib/quizzes.js，可扩展）

flower（你是什么花，3 题 8 结果）· animal（你是什么小动物，3 题 8 结果）· career（职业方向倾向，3 题 6 结果）· energy（今日能量提示，0 题，基于画像生成）。题目为通用趣味心理映射题；结果由 LLM 主持选择并做画像个性化收尾，自动存入 `profile.tests`。

## 14. 运行与部署

```bash
cd star-map
npm install
copy .env.example .env   # 填 DEEPSEEK_API_KEY；不填自动 Mock 模式（整链路仍可跑）
npm run dev              # http://localhost:3000
npm run import ../data/演示数据-7天日记.md   # 一键装载演示数据（或用户自己的日记）
npm run reset            # 清空画像
npm run eval             # 抽取质量评测
```

- 双模引擎：有 Key 走 DeepSeek（`deepseek-chat`，response_format=json_object），无 Key 全部规则 Mock 兜底，演示不依赖网络。
- 技术栈：Next.js 15（App Router + API Routes）· React 19 · 文件存储（profile.json/days.json）· SVG 2.5D 星图（P1 升级 Three.js 3D）。
- 关键决策：主题归并由 LLM 输出 mergeToId（MVP 不引入向量库，主题 >100 再升级 Chroma）。

## 15. 已知限制与 Roadmap

**已知限制**：单用户本地存储无数据库；语音输入依赖浏览器 Web Speech API（Chrome/Edge）；星图 asOf 回放的主题 freq 不回退（近似）；行为层为规则版（LLM 深度抽取待做）；无真实注册体系。

**Roadmap**：
1. 观察反馈接入画像自迭代（feedbackLog 已存证）；
2. 星星拖拽交互（现为按钮版）；
3. 保存链路提速（抽取异步化）;
4. 价值层画像（立场/红线）与价值观遵循注入；
5. 每 7 天"画像修正摘要"周期自复盘（adaptLog）；
6. 3D 粒子星图 + 时间轴滑块；
7. 评测集扩到 50+、双人标注 kappa、对话质量 rubric 自动化。
