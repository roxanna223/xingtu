# 「星图」求职材料：作品说明 + 面试话术 v0.1

> 投递腾讯 AI 产品岗专用。写作口径：面试官最关心的是**你对用户/行业/AI 边界的判断**，不是功能数量。所有表述与代码、文档一一对应，可被追问。

## 一、作品一句话

「星图」是面向 20–35 岁人生转折期人群的 **AI 自我状态导航产品**：通过长期对话建模用户内在状态，生成一张 **会演化的内心星图**，并输出一条明确的可执行路径。核心循环：**看见 → 理解 → 指路 → 陪走 → 复看**。配套三套系统：**建议采纳闭环**（指路验证）、**Skill 注册表 + 调度器**（4 技能、确定性路由优先）、**目标系统 v2.2**（主客观两分法 + 细分项 + 积分彩蛋）。

## 二、为什么做（行业洞察，面试开场用）

**用户侧四条痛点**：
1. 焦虑泛化、思绪碎片化，缺乏整体视角；
2. 单次 AI 对话无记忆，聊完即忘，无法形成长期认知；
3. 心理测评娱乐化，测完无后续、无行动路径；
4. 人生决策期（实习/求职/考研考公/转行/婚育）缺"状态定位 + 指路"服务，专业咨询贵且门槛高。

**市场侧结论**（我扫描了 3 个相邻赛道共 12+ 款产品）：
- AI 陪伴/记录（心光、Me.bot）：有长期记忆，无状态结构化与路径输出；
- AI 命理（人生K线、DeepChow）：明面玄学、单次报告、娱乐向；
- 内心可视化（心镜、知镜、Loom、Soularsystem）：状态→星图快照，但单次、无演化、无指路。

**一句话洞察**：用户不缺一个聊天机器人，缺一个**能长期记住他、把他自己讲不清楚的状态讲清楚、并给出下一步的导航器**。我的机会窗口是"长期建模 + 结构化状态 + 可视化 + 路径输出"的完整闭环——单点都有人做，闭环没人做透。

## 三、目标用户与分层交付

- 主战场 20–35 岁，核心 20–30 岁转折期人群，三段细分：
  - 20–23 在途期（实习/求职/升学抉择）
  - 23–27 立业期（职场方向摇摆、内耗）
  - 27–35 转折期（转行/晋升/婚育/创业）
- **分层交付策略**：高认知用户给逻辑与规律（心理学术语、成因推导），结果导向用户直接给结论与动作；由暗层画像判定（抽象词密度、追问行为等信号），不在明面暴露。

## 四、产品方案（MVP 已全链路落地 + 三套闭环系统）

闭环五步：**采集**（每日引导式对话）→ **建模**（暗层画像引擎抽取"主题-情绪-关联"三元组并归并）→ **呈现**（2.5D 星图）→ **指路**（叙事优先状态报告）→ **反馈**（回写画像，星图微调）。

**① 建议采纳闭环（指路验证 Q6）**：报告建议下「✅ 我做到了 / ✗ 还没做」→ adoptions 存证（含标记时刻主题极性快照）→ 后续报告输出「回看」："上次建议 X，你标记做到了；该主题极性从 -0.6 回到 -0.25"→ 周期报告输出采纳率。北极星过程指标（建议采纳率）落地。

**② Skill 注册表 + 调度器**：陪伴对话里的能力抽象为 4 个 Skill（quiz 测验 / energy 能量提示 / goalBreak 目标拆解 / quickStart 快速开始），统一接口 + **确定性路由优先 + LLM 意图兜底**，每次调度落 skillLog（来源/结果），后台统计触发与完成。配套「Skill 三标准」（注册/评测/下线）——**我定义了 Skill 的质量与可运营标准**。

**③ 目标系统 v2.2（路线图 P2 提前落地）**：goalBreak 拆解自动落「计划」栏目 → 记录/聊天双通道自动同步进度 → 计划页展示完成度/打卡日志/积分流水/完成轨迹 → 小星首轮主动提醒。五维度框架：行动力（每日可重复打卡+结转）/ 可行性（metric 数字=达标天数）/ 记录感（主客观两分法：客观一键完成、主观填数据）/ 激励（积分账户+每日 AI 彩蛋任务+连续加成+等级）/ 复盘。**主客观铁律**：只答"是/否"就能完成量化=客观，需要具体数据=主观，量化数据必须在产品内采集。**细分项**：三餐→早餐/午餐/晚餐独立记录独立计分，随时记 + 随手记 AI 梳理（含否定过滤："晚饭还没吃"不落档）。

星图视觉语义：粒子=念头主题；颜色=情绪极性；大小=提及频率；亮度=近期活跃度；连线=共现关联；时间轴=状态演化。六域分区：事业/关系/自我/健康/财务/成长。

报告为**叙事优先**结构：今日心情色（颜色+解读）→ 心情轨迹（事件×情绪）→ 今日回放（用用户原话客观重述）→ 我注意到（2~3 条观察，每条附原话引用）→ 可以试试（可选建议，仅当用户表达困扰或为长期模式，且通过四问过滤）→ 下一句（引导继续记录）。粒度覆盖日/周/月/季/年。**反编造四机制**：证据落地（观察必附原话）→ 叙事优先（先重述事实）→ 最小推断（cohort 永不作判定依据）→ 宁可少说（证据不足就少写甚至不写）。

## 五、AI 结合深度（重点章节）

1. **长期记忆**：画像 JSON 结构化增量存储；不做"全量历史塞 prompt"，而是每日抽取归并——这是 LLM 长期用户建模的成本可控路径。
2. **画像引擎**：抽取 Prompt 强制六域归类、八情绪枚举、极性量化；主题归并由 LLM 输出 `mergeToId` 完成（MVP 刻意不引入向量库，主题 >100 再升级——复杂度控制决策）。
3. **状态可视化**：把 LLM 输出的离散三元组映射为持续对象（星图），解决"报告看完即忘"——图是每天回来会变化的留存钩子。
4. **报告生成**：画像摘要 → 叙事优先报告（回放 → 带原话引用的观察 → 按意图与尺度决定是否给建议 → 下一句）；建议逐条过四问过滤（对象只能是自己 / 可控 / 不伤关系 / 长期成长有用）；分层话术双模板（逻辑版/结果版）；周期报告（日/周/月/季/年）同价值观；硬性约束禁止命理词汇、禁止编造因果、路径必须可执行。
5. **文化符号特征工程**：出生年月 → cohort 特征（代际、成长经济周期、年龄人生任务）作为画像先验注入。**口径：中国用户习惯用命理语言自我叙事（"我命不好""水逆"），产品把这套文化隐喻翻译为可计算特征，与用户对齐认知框架——命理语言是文化接口，不是科学依据。**明面绝不展示玄学内容。
6. **反馈闭环**：反馈回写主题权重与极性，影响后续报告生成（连续负面反馈会切换路径类型）。
7. **双模引擎**：LLM 主引擎 + 规则 Mock 兜底，演示永远不依赖网络状态（工程可靠性也是产品决策）。
8. **安全边界**：危机信号识别 → 报告置顶转介语与心理援助热线 12356；定位为自我认知工具，非医疗非治疗。
9. **指路验证闭环**：建议采纳标记 → 极性快照 → 报告回看（LLM 生成 + 确定性兜底，只引用真实数据）——"建议是否有效"有了可度量的证据链。
10. **Skill 调度（Harness 思想）**：上下文组装 / 记忆管理 / 工具调度 / 输出约束 / 评测环五件套；确定性路由优先 + LLM 兜底，调度全程留痕。
11. **目标系统的 LLM 应用**：拆解（goalBreak：主客观分型 + 细分项）→ 同步（记录/聊天文本 → LLM 判定步骤完成/相关 + 规则兜底）→ 梳理（随手记 → structuredLog 分派到细分项，否定过滤）→ 激励（每日彩蛋任务 LLM 个性化生成）——同一个产品里 LLM 承担四种不同职责。

## 八、面试 Q&A 预设（14 题）

**Q1 和豆包/心光/Me.bot 有什么区别？**
A：三者都不做"状态结构化 + 指路"。豆包无长期记忆；心光有记忆但明确克制可视化与输出；Me.bot 偏记录复盘。星图的差异在"输出一条可执行的路"——陪伴与记录是手段，指路是目的。

**Q2 星图是不是炫技？信息增量在哪？**
A：每条视觉编码都有语义（颜色=极性/大小=频率/亮度=活跃/连线=共现/时间=演化）。它把"散落的自我叙事"变成"可回放、可对比的趋势数据"，自我报告的情绪时间轨迹本身有心理学价值（CBT 常用情绪追踪）。而且图是持续对象，每天变化构成留存钩子，解决报告"看完即忘"。

**Q3 为什么用八字/命理？科学性怎么解释？**
A：明面完全不用。暗层把出生年月转为 cohort 特征（代际、经济周期、年龄人生任务）注入画像先验，这是社会科学站得住的。命理语言是中国用户的自我叙事文化接口，产品翻译为可计算特征以对齐认知框架；不排盘、不预测吉凶、不制造焦虑。

**Q4 长期建模怎么防记忆漂移/幻觉？**
A：①结构化增量存储而非全量历史入 prompt；②每次抽取附已有主题列表，强制归并决策，防止主题爆炸；③极性滚动平均，稀释单次噪声；④每条主题保留原文引用，报告可溯源；⑤反馈回写纠偏；⑥上线前建抽取准确率评测集。

**Q5 冷启动：7 天才出完整图，用户为什么坚持？**
A：①Day1 onboarding 即产生 3 个种子主题，当天就有第一张星图；②3 天首图承诺 + 每日打卡；③报告次日更新构成每日钩子；④长期看星图是"成长资产"，迁移成本随使用上升。Demo 用预置数据绕开，文档保留解法。

**Q6 心理产品合规边界？**
A：定位自我认知工具，非医疗非治疗；危机信号 → 转介语 + 热线 12356；画像透明、可删除；不做疾病诊断；上线需心理专业顾问评审 prompt 与话术。

**Q7 商业化？**
A：三阶段：免费（积累数据与留存）→ 订阅（报告深度/多端/自定义生活域）→ B 端（企业 EAP、高校就业中心，脱敏 cohort 报告）。不做广告，数据不出画像。

**Q8 为什么 LLM 归并而不是向量库？**
A：MVP 主题 <100，抽取阶段让 LLM 直接输出归并决策，准确率高于纯余弦阈值，且少一个服务少一类故障；主题规模或实时聚类需求出现时再升级向量库。复杂度控制是刻意的。

**Q9 如果腾讯让你做，第一步做什么？**
A：先定北极星指标（报告帮助率）+ 冷启动 A/B（3 天首图 vs 7 天首图）；把星图做成可分享的社交货币测传播；探索微信小程序形态与元宝/混元生态入口。先做减法验证"指路"和"星图"哪个才是用户留下来的原因。

**Q10 指标怎么定？**
A：北极星=周活跃记录天数。护栏=报告帮助率≥60%、主题归并准确率≥90%、危机转介触达率 100%。增长=星图分享率。

**Q11 怎么验证"指路"有效？**
A：已落地「建议采纳闭环」：报告建议下可标记"我做到了/还没做"，标记时快照主题极性，后续报告输出回看——"上次建议 X，你标记做到了；该主题极性从 -0.6 回到 -0.25"，周期报告给采纳率。长期验证：对照实验（有路径 vs 无路径组）比较主题极性演化斜率，框架已写入 roadmap。

**Q12 技术难点最大在哪？**
A：不是生成，是"长期准确的用户建模"——抽取稳定性、主题归并的语义漂移、画像置信度表达、自由文本情绪校准。可视化渲染是确定性问题，建模是开放问题。

**Q13 为什么投腾讯？**
A：（结合自己真实想法改写以下骨架）①长期陪伴场景与微信生态天然契合；②元宝/混元 API 生态；③腾讯的社交与可视化叙事基因；④这种产品需要国民级信任背书。可补一句：我研究过元宝的产品思路，星图的"长期记忆+指路"与"AI 实用价值"方向一致。

**Q14 你在项目里的角色？**
A：如实：独立完成产品定位、市场扫描、功能规格、数据模型、Prompt 工程与验收标准；前端页面由 AI 辅助生成（我提供规格与验收），后端引擎与闭环逻辑自己实现。**强调自己做的部分是产品决策与 AI 建模，不是写页面。**

**Q15 为什么把对话能力抽象成 Skill？调度策略怎么定？**
A：能力散落（测验/能量提示/目标拆解）无法度量、无法治理。我做了统一 Skill 接口 + 三标准（注册：有明确价值、可路由、可结构化输出；评测：调度留痕 + 触发/完成率看板；下线：连续 2 周低触发进观察名单）。调度=**确定性路由优先 + LLM 意图兜底**——规则可解释、稳定，LLM 兜底覆盖面；goalBreak 命中走快路径。这对应大厂 Agent 产品里的 Skill/MCP 治理问题，只是我在 0-1 产品里完整跑了一遍。

**Q16 目标系统的"主客观"是怎么定义的？为什么这么分？**
A：铁律——客观 = 用户只回答"是/不是"就能完成量化（"今天 11 点前睡"）；主观 = 量化需要具体数据（"记录三餐"需要吃了什么，只答"记了没记"不算量化）。因为本产品是量化工具：**量化数据必须在产品内采集**（快捷选项/自由输入），不能假设用户去别的工具量化后回来点"是"；拿不准一律归主观。反面例子：把"记录三餐"做成点一下就完成，数据是空的，量化名存实亡。

**Q17 随手记 AI 梳理怎么保证准确？**
A：三道防线——① LLM 结构化分派（提示词约束只归"实际发生"的内容）；② 规则兜底（细分项名称/时段词 + 子句级否定识别："晚饭还没吃"不落档）；③ 服务端最终安全过滤（否定表达式兜底，全否定给友好提示）。真实案例："中午吃的盖饭，晚饭还没吃"→ 只记午餐"盖饭"；"晚上还没到"→ 不落档。
