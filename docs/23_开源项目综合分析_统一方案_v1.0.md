## 2. 决策基线（来自 18 号纪要）

1. 记录模块拆为「日记」模块：手动记录=每日归档文档，不强制，不再判定"今天是否已记录"；
2. 小星=自我进化智能体：初始提示词一致，随使用沉淀每账户个人资产进化提示词，存账户数据库；
3. 日报=对话+日记的归纳，**次日 6:00 刷新**，以「目标/自我/差距」三坐标生成成长规划；
4. 记录页改造顺序：先看调研再动。

三条宪法级红线（初心文档）：助手姿态不评判；危机信号转介 12356；明面禁命理；进化层不得覆盖红线。

## 3. 模块级"最优蓝本"合并结论

### 3.1 小星进化层（个人资产）← 16 + 19

- **资产条目数据模型**：ECC instinct 契约（id/trigger/behavior/confidence/domain/evidence/trust/updatedAt），domain 换成星图语义：`沟通风格 / 情绪模式 / 关心主题 / 目标偏好 / 建议偏好 / 人生阶段`。
- **记忆载体**：ReMe 的"Memory as File"——每账户资产目录下 Markdown 事实源 + `meta.json` 索引（兼容现有 JSON 存储，天然可导出/审计/删除，满足"个人资产"定位）。
- **记忆分层**：Letta core memory 三分——`self`（我是谁：长期身份/价值观）`persona`（小星与用户的关系与说话方式）`working`（近期活跃：本周主题/进行中目标），映射星图画像三层的升级。
- **反思时机**：Letta sleep-time compute → 星图的"6:00 日报生成"同时执行一次后台反思（reflection），产出"记忆编辑"（新增/合并/降权）——**日报与进化共用一次后台作业**。
- **置信度演化**：ECC 规则（确认 +0.05 / 用户纠正 −0.1 / 周衰减 −0.02），用户纠正入口=现有反馈组件（说得对/不太对/建议采纳标记）。
- **晋升治理**：rules-distill 三层过滤（多次证据 / 可行动 / 违反风险）+ 用户可审，绝不自动变硬规则。
- **观察管线**：现有 chats.json 全量持久化已满足"确定性采集"；异步抽取升级为"观察者"（低成本模型），检测四类信号：用户纠正 / 有效互动 / 重复模式 / 偏好表达。

### 3.2 6:00 日报与坐标体系 ← 19 + 22

- **划日规则**：自然日以 **6:00 为界**（6:00 前的内容归前一天）；日报 `reportKey = date`，覆盖 [date 06:00, date+1 05:59)。
- **生成机制**：懒触发（用户 6:00 后首次访问时生成，幂等去重）+ 可选 `node-cron` 预生成（抄 n8n cron+队列+幂等思想，自建轻量实现，不引平台）。现有 `/api/report` 缓存机制直接复用，仅改日期切分与触发判定。
- **坐标体系**（Generative Agents 的 reflection 结构落地）：
  - **目标**：用户明说的目标 + 进行中计划（现有 goals 系统）+ 长期意图；
  - **自我**：我是什么样的人 / 情绪与行为模式 / 价值倾向（来自进化层 self 块与日记归纳）；
  - **差距**：现状与目标之间的差距 = 观察（带原话证据）− 期望，只陈述不评判；
  - **成长规划**：对差距给出"本周可执行的一小步"（沿用四问过滤：对象是自己/可控/不伤关系/长期有用），并回写目标系统。
- **内容来源**：对话（/api/star 会话）+ 日记文件，两者按时间窗聚合为事件流（见 3.4），再进 LLM 归纳。

### 3.3 小星智能体封装（多技能路由）← 16 + 22

- **Character 层**：借鉴 Eliza 的 Character/Provider/Evaluator JSON schema，小星 = 基座人格（全员一致）+ 进化层（按账户注入，注入前压缩为有界摘要，抄 ECC `ECC_SESSION_START_MAX_CHARS` 有界注入思想）。
- **技能路由**：现有 skills.js 的"确定性路由优先 + LLM 兜底"保留，能力目录扩展为：测验 / 目标拆解 / 能量提示 / 记录引导（新）/ 个人定位（新）/ 情绪承接闲聊。抄 LangGraph 的"状态机 + checkpoint + thread"思想做会话与草稿状态，不引入 LangGraph 依赖。
- **开场主动权**：用户先开口；空界面推荐发送卡片（已有 /api/star suggestions 生成器）；**记录引导卡片**=心理侧写式（见 4.2，待 20 号调研补强）。
- **入口合并**：记录页的"和星图聊聊"并入小星；主页两大入口改为「和小星聊聊」+「写日记」。

### 3.4 日记模块 ← 17 + 21

- **数据层**：抄 Logseq——每账户 `journals/YYYY_MM_DD.md` 一文件，属性后置（`心情:: 平静`、`事件:: 面试`），每日可选模板，全部纯文本可导出。
- **统一事件流**：抄 ActivityWatch `{bucket, event:{timestamp, duration, data}}`——日记段落、AI 对话轮、情绪点选、目标打卡统一为带时间戳事件，**日报 = 对 [date 06:00, date+1 06:00) 时间窗的事件聚合**，天然解决"日记+对话一起归纳"。
- **编辑器**：抄 SilverBullet（MIT、浏览器原生 TS、轻量）——斜杠命令 + 模板 + frontmatter 的交互模式，用现有 React textarea 渐进实现，不引重型块编辑器。
- **最低摩擦入口**：主页常驻"打开即当天"日记卡（1 次点击）；输入形态=一句话起笔 + 情绪点选（10 秒档）+ 语音转写 + 可选"今日一问"轻引导（可跳过、不强制）。
- **AI 读写边界**：抄 Trilium ETAPI 思想——日记条目带稳定 ID，日报"引用原话"落到句/段粒度。
- **不强制**：无日记内容时日报只归纳对话，不催写。

### 3.5 心理陪伴与对话质量 ← 20

- **对话框架**：CPsyCoun 的"咨询报告 6 部分结构"（标题/类型/方法/个案简述/咨询过程/经验感悟）→ 映射为小星结构化产出模板（个人定位、引导记录梳理卡的字段设计直接取材）；SoulChat 的"共情-倾听-安慰"三能力 → 写进小星系统提示词的话术顺序（先倾听承接 → 共情 → 温和引导，与现有"情绪承接优先"一致并更具体）。
- **对话质量裁判（P0 自建）**：CPsyCoun 的 4 维评测 rubric（全面性/专业性/真实性/安全性）+ 逐轮带历史的 LLM 裁判法 → 星图评测脚本（现有 eval-extraction.mjs 扩一版"对话裁判"），用 CPsyCounE/PsyBench 等中文评测集当题目。
- **模型策略**：开源心理模型（EmoLLM/MindChat/SoulChat 等 7B/13B）只做 DeepSeek 之外的对比基线（P1），不替代；权重商用许可需逐条核对（部分标注"需确认"）。
- **危机识别**：开源界无"识别+转介"现成工程——星图**自研**（现状规则+LLM 双层已可用），仅借鉴 MentalLLaMA/SMHD 的自伤/抑郁信号分类思路扩充关键词与语义覆盖。
- **红线**：不引入任何"诊断/量表打分"倾向的组件——LLM 不诊断、不打 PHQ-9/GAD-7 分，与"非医疗非治疗"保持一致。

### 3.6 可视化 ← 22

- 星图 3D 升级：`react-force-graph-3d`（快出效果）或 `@react-three/fiber + drei`（深定制星空粒子/星座连线）；`tsParticles` 做星空氛围背景。SVG 版保留为降级。
- 视觉语言不变：心情色八情绪、不做正负标注、生活域分区。

## 4. 统一方案（落地设计）

### 4.1 小星智能体封装方案

```
基座提示词（lib/xiaoxing/character.json，全员一致）
  ├─ 人格：小星，人生导师助手；助手姿态/不评判/危机转介/禁命理（硬约束）
  ├─ 能力目录（skills.js 扩展）：quiz / goalBreak / energy / recordGuide / positioning / chat
  └─ 路由：确定性路由优先 + LLM 兜底（现状保留）
进化层（账户资产，每用户 data/<uid>/persona/ 下）
  ├─ self.md / persona.md / working.md   ← Letta 三分 + ReMe 文件即记忆
  ├─ meta.json（instinct 条目：id/trigger/behavior/confidence/domain/evidence/trust）
  └─ 注入：会话开始时读取 → 压缩为有界摘要（≤800 字）→ 拼入系统提示
进化作业（与 6:00 日报同批运行，后台异步）
  观察（每轮对话落盘，确定性）→ 抽取四类信号（低成本模型）→ 置信度升降 →
  晋升审核（三层过滤 + 用户可审）→ 写入 persona 资产
```

数据与红线：
- 资产文件属于用户：可查看 / 纠正（降权）/ 删除 / 导出（数据权利）；
- `trust: unreviewed` 默认；晋升为"稳定设定"需用户在设置页确认；
- 红线（危机/命理/医疗边界）硬编码优先，进化层永不覆盖。

### 4.2 小星"记录引导"模式（心理侧写式框架）

> 话术框架基于 20 号调研定稿。设计基线：
> - 用户从推荐卡片点击"帮我理一理今天"才进入引导；第一句始终由用户发起；
> - 引导三原则：**不审问**（不用"今天情绪起伏最大的时候"式高压问题）、**不废话**（每句都要引出可记录内容）、**跟着用户走**（用户聊到哪接到哪）；
> - 话术顺序（SoulChat 三能力工程化）：**倾听**（复述用户原话锚点）→ **共情**（命名情绪，不评判）→ **轻引导**（一次只问一个具体、低压力、可跳过的问题；参照 CPsyCoun 咨询过程的"逐轮单点推进"）；
> - 引导产出：轻量梳理卡（可编辑）→ 落日记文件（非强制字段）+ 抽取进画像；
> - 对话质量裁判：4 维 rubric（全面/专业/真实/安全）定期抽样评估，安全维专门检查"是否出现诊断式表达/命理词汇/未触发危机转介"。

### 4.3 日记模块重做方案

- 页面：`/diary`（原 /record 改造），主页入口「写日记」；
- 打开即当天文件；顶部：日期 + 情绪点选 chips + 天气/事件可选属性；
- 主体：自由书写区（SilverBullet 式斜杠命令：`/心情` `/事件` `/目标` 插入属性）；
- 底部："今日一问"（轻引导，可换一换/跳过）+ 语音转写按钮；
- 每次保存：段落按 ID 落事件流 → 抽取管线复用（异步）→ 次日 6:00 进日报；
- 回顾：日记内嵌"那天小星怎么看"（引用日报段落）；日历视图 P1。

### 4.4 6:00 日报 + 目标/自我/差距坐标方案

- 报告结构（日报）：
  1. 昨日回放（事件流按时间重述，引用日记/对话原话）；
  2. 心情轨迹（情绪点选 + 对话情绪抽取）；
  3. **三坐标**：目标（进展：进行中目标 X/N + 意图）/ 自我（模式观察，带证据）/ 差距（客观差距 + 指向自身的小步建议）；
  4. 成长规划：本周一小步（四问过滤）→ 可一键加入计划栏目（复用 goalBreak）；
  5. 下一句（明天的具体话题）。
- 生成：6:00 划日 + 懒触发幂等生成（现有缓存升级）+ 可选 cron 预生成；生成后同一作业执行进化反思（sleep-time compute）。
- 用户主权：观察反馈（说得对/不太对）、建议采纳标记（已有）继续回写。

### 4.5 存储演进（保守路线）

- 事实源不变：每用户 JSON/Markdown 文件（ReMe 精神：文件即记忆，可审计可导出）；
- 新增：`journals/` 日记目录 + `persona/` 资产目录 + `events.jsonl` 事件流（追加式）；
- 不动 PostgreSQL：当前规模 JSON 足够；日活主题/事件超阈值后再迁（沿用 README 的复杂度控制决策）。

**风险复查（与初心三问对照）**：本方案所有新增能力都通过——①帮用户看清（事件流+三坐标+日报引用原话）②帮用户走（成长规划一键入计划）③尊重人（进化层用户主权、记忆≠指令、不诊断不量表、危机转介保留、红线硬编码优先）。
