## 1. 信息架构

三页面 + 一个反馈组件，MVP 不做登录注册（本地单用户演示）：

```
采集页（/）→ 常驻对话（主）或 快速表单（辅）→ 提交 → 画像引擎（暗层）
星图页（/star-map）← 画像 JSON
报告页（/report）← 画像 JSON + LLM 生成
反馈组件（报告页内嵌）→ 回写画像 → 星图/报告微调
```

页面导航：底部 Tab 或顶部 Nav（采集 / 星图 / 报告）。

### 1.1 常驻对话模式（v0.2 新增，主交互）

**设计原则**：用户不想填表就不填——主路径是和 AI 对话，AI 温和引导（承接情绪 → 找锚点 → 收束），产出可编辑的"今日梳理"草稿，用户确认后落星图。

- **对话约束**（写入 System Prompt）：**情绪承接优先，无轮数上限**——跟着用户节奏一句一句听，绝不主动切换话题、绝不催促；仅当用户明确表示结束（"就这些/好了"）或点击"帮我梳理"按钮时才收束；每条回复 ≤40 字、口语化共情、不评判不给建议（建议是报告阶段的事）；禁用命理词汇；危机表达先关怀+附热线 12356；可自然衔接昨日记录。
- **梳理主动权在用户**：聊天框旁有"✨ 帮我梳理今天"按钮；AI 只在用户示意后产出草稿。
- **输出协议**：每轮严格 JSON `{reply, draft, done}`；done=true 时 draft 含 `{q1, q2[], q3, summary}`。
- **衔接**：开场可引用昨日记录（"昨天你说的那件事，今天还在吗？"）。
- **草稿可编辑**：用户直接改卡片字段，或继续对话口述修改（draft 作为上下文回传，模型在既有草稿上更新，不丢弃已确认内容）。
- **情绪轨迹**：q2 为字符串数组，每条格式"情绪：因为……"（对应具体事件），草稿与快速记录共用轨迹编辑器，支持多条、可删改；一天的情绪变化（如焦虑→充实）得以保留。
- **保存**：确认后以对话原文为 freeText、草稿字段为 q1/q2/q3 走 /api/record，引擎流程不变。
- **语音输入**：Web Speech API（zh-CN），失败时明确提示原因与降级路径；**语音输出**：每条 AI 回复可点击朗读 + "自动朗读"开关（固定中文音色）。

**接口**：`POST /api/chat`，入参 `{messages[], draft|null}`，返回 `{reply, draft, done}`；无 Key 时规则版 mockChat 兜底。

## 2. 页面 1：采集页（/）

> ⚠️ 演进指针（P0-1，2026-08-24）：对话原文已全量持久化到 `data/chats.json`（会话制，刷新可恢复、当日已保存时自动回到"已保存"态），未保存的对话内容也会并入画像。采集链路实现见 `00_总文档_v1.0.md` §4.1。

目标：10 分钟内完成一次高质量记录，抽取质量优先于时长。

### 2.1 组件清单

| 组件 | 规格 |
|---|---|
| 顶部问候 | 按时间段问候 + 一句话昨日报告摘要卡片（第 2 天起显示，例："昨天你提到最多的是'转行焦虑'，今天它还在吗？"） |
| 引导语 | 首次："随便说，说得越乱越好——我来帮你理顺。"（降低表达压力，暗示产品能力） |
| 自由倾诉框 | 多行 textarea，占位符示例："今天最累的那一刻是什么？" |
| 收束三问 | 固定三题，每题一行输入框：Q1 今天最耗能的一件事；Q2 那一刻的情绪是什么（给 8 个情绪词点选 + 自由填写）；Q3 明天最在意的一件事 |
| 提交按钮 | 主按钮"记录今天"；提交后转菊花 3~5 秒（后台跑抽取），完成跳转星图页 |

### 2.2 情绪词表（Q2 点选项，8 个）

焦虑 / 疲惫 / 迷茫 / 愤怒 / 平静 / 期待 / 低落 / 充实（可多选）。

### 2.3 首次引导（Day 1 onboarding，独立半屏）

采集三组基础信息（**不告知用途**，只说是"让我更了解你"）：
1. 出生年月（cohort 用，暗层）
2. 当前职业阶段（在校 / 实习 / 工作 1-3 年 / 工作 3 年以上 / 自由职业 / 待业）
3. 当前最纠结的三件事（各一句话）

## 3. 页面 2：星图页（/star-map）

### 3.1 画布规格

- 深空背景：径向渐变 `#0a0e1a → #05070f`，撒 60~120 颗静态背景星点（微弱闪烁）。
- 六域分区：画布按 2×3 或环形排布六个"星座区"，每个区一个淡色区域光晕 + 域名称签（事业/关系/自我/健康/财务/成长）。
- 2.5D：Three.js 透视相机固定俯角（约 30°），允许拖拽水平旋转 + 滚轮缩放；降级方案为 SVG 平面图。

### 3.2 粒子规格（一个粒子 = 一个念头主题）

| 属性 | 映射 | 取值 |
|---|---|---|
| 位置 | 所属生活域的分区内随机/主题向量投影 | 分区内 |
| 颜色 | **心情颜色**（八情绪专属色，不做正负向标注） | 焦虑=蓝紫 `#7b8cff`、疲惫=灰蓝、迷茫=雾灰、愤怒=红、平静=青绿、期待=金 `#f5c76a`、低落=深蓝、充实=暖橙 `#ff9a5c`；图例只写"颜色 = 心情" |
| 大小 | 提及频率 × 近期活跃度 | 直径 6~28px |
| 亮度/发光 | 近期活跃度（7 天内越近越亮） | 光晕强度 0.2~1.0 |
| 连线 | 主题共现关联 | 线宽 1~4px，同域线偏域色，跨域线白色半透明 |

### 3.3 交互

- 拖拽 = 旋转；滚轮/双指 = 缩放；悬停粒子 = 显示主题名 tooltip。
- 点击粒子 → 右侧滑出详情卡片：主题名、所属域、情绪标签、最近活跃时间、1~2 条原文引用、关联主题列表。
- 顶部工具条：图例开关（情绪颜色图例）、报告入口按钮（"查看我的状态报告"）、`[P1]` 时间轴滑块（回放 7 天演化）。

### 3.4 空状态与首图承诺

- 记录不足 3 天：星图区域显示"再记录 X 天，你的星图就会出现"（首图承诺，解决冷启动感知）。

## 4. 页面 3：状态报告页（/report）

> ⚠️ 本节为 v0.1 初版规格。报告结构已演进为**叙事优先版**（回放 → 带原话引用的观察 → 按意图与尺度决定建议 → 下一句，日/周/月/季/年五粒度），**以 `08_report_framework_v0.1.md` 与 `00_总文档_v1.0.md` 为准**。下方"五段式（判定+置信度+根因链）"为历史版本，仅供参考产品演进过程。

### 4.1 报告五段结构（与基调文档一致）

1. **当前状态判定**：一句话定性 + 置信度（例："你正处于'立业期方向摇摆'状态，主要耗能源是事业域的不确定感。置信度 82%"）。
2. **星图解读**：主导域、活跃主题 Top3、情绪分布比例条。
3. **压力根因链**：现象 → 近因 → 远因，3 层，每层一行 + 依据引用。
4. **路径建议**：一条明确的路 = ①下一步可执行动作（本周内可做）②预期状态 ③验证信号（什么现象说明有效）。
5. **下一句**：以提问收尾引导用户继续记录（"明天我们可以只聊一个问题：__"，保持闭环）。

### 4.2 分层话术

- 报告底部有"看逻辑版 / 看结果版"切换按钮（显式切换，MVP 简化实现；暗层自动判定是后续优化）。
- 逻辑版：含心理学概念、成因推导、数据依据；结果版：只保留判定、路径建议、一句话原因。

### 4.3 反馈组件（闭环关键）

- 报告末尾："这份报告对你有帮助吗？"（有帮助 / 没帮助）+ 一句话原因输入框。
- 提交后 Toast："已记下，明天你会看到星图的变化" → 回写画像（调整相关主题权重/情绪标签），下次报告引用该反馈。

## 5. API 设计（Next.js API Routes）

| 接口 | 方法 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| `/api/record` | POST | `{date, freeText, q1, q2, q3}` | `{newTopics: [], updatedTopics: []}` | 调 LLM 抽取三元组 → 更新画像 JSON |
| `/api/onboard` | POST | `{birthMonth, careerStage, worries[]}` | `{ok}` | 写 cohort 特征与初始主题 |
| `/api/star-map` | GET | `date?` | `{nodes[], edges[]}` | 读画像 JSON 输出星图数据 |
| `/api/report` | GET | — | `{judgement, domains, rootCauses[], path, confidence}` | 画像摘要 → LLM 生成报告 |
| `/api/feedback` | POST | `{helpful, comment}` | `{adjusted: []}` | 回写画像 |

## 6. 画像引擎规格（暗层，本产品的技术灵魂）

### 6.1 数据模型（画像 JSON）

```json
{
  "user": {
    "cohort": { "birthYearMonth": "2001-09", "generation": "Z世代", "lifeTask": "立业期探索" },
    "careerStage": "实习",
    "personaTier": "logical"   // logical | result，暗层判定
  },
  "topics": [
    { "id": "t1", "name": "转行焦虑", "domain": "事业",
      "emotion": "anxiety", "polarity": -0.6,
      "firstSeen": "2025-01-01", "lastActive": "2025-01-07",
      "freq": 9, "quotes": ["...", "..."], "linkedIds": ["t2"] }
  ],
  "edges": [ { "source": "t1", "target": "t2", "weight": 0.7 } ],
  "feedbackLog": [ { "date": "...", "helpful": true, "comment": "..." } ],
  "emotionSeries": [ { "date": "2025-01-01", "topEmotion": "anxiety", "intensity": 7 } ]
}
```

### 6.2 抽取 Prompt 规格（POST /api/record 用）

输入：当日记录全文 + 现有主题列表。输出（严格 JSON）：
`[{topic, domain, emotion, polarity, intensity, relatedTopics[], quote}]`
- `domain` 只能从六域选，Prompt 中附每域定义与判定规则：
  - 事业：工作/学业/实习/求职/晋升/转行
  - 关系：家人/伴侣/朋友/同事/社交
  - 自我：自我认同/价值感/性格/习惯/内耗
  - 健康：身体/睡眠/运动/心理压力躯体化
  - 财务：收入/支出/储蓄/负债
  - 成长：技能学习/兴趣/认知提升
- 主题合并：新主题与现有主题语义相似度 ≥ 0.75（Chroma 余弦）→ 并入旧主题，更新 freq/lastActive/emotion 均值，追加 quote；否则新建。**（v0.1 落地实现：由抽取阶段 LLM 直接输出 mergeToId 完成归并，暂不引入 Chroma，主题 >100 后升级向量库——复杂度控制的刻意决策，README 有记录）**
- 情绪极性：-1（极度负向）~ +1（极度正向）。

### 6.3 报告生成 Prompt 规格（GET /api/report 用）

输入：画像 JSON 摘要 + cohort 特征 + 反馈历史。输出五段结构（见 4.1）。
硬性约束（写入 System Prompt）：
- 只输出产品明面语言，**禁用八字/六爻/命理词汇**；
- 路径建议必须是"本周内可执行"的具体动作，不输出鸡汤式 tip；
- 若检测到危机信号（自伤/自杀语义），报告顶部插入转介语与干预热线提示（如心理援助热线 12356）。

### 6.4 Cohort 特征表（静态预置，不实时排盘）

| 出生年段 | 代际标签 | 人生任务（注入报告） |
|---|---|---|
| 2003-2008 | Z 世代早期 | 在途期：探索方向、建立第一份职业认同 |
| 1995-2002 | Z 世代 | 立业期：职业方向收敛、经济独立 |
| 1989-1994 | 千禧初段 | 转折期：晋升/转型/家庭重大决策 |

> 文档口径：文化符号资产的工程化使用（详见基调文档第 8 节）。代码注释与文档中一律用 "cohort 特征"，不用 "八字"。

### 6.5 Persona 分层判定（暗层信号）

- 逻辑型信号：抽象词密度高、爱问"为什么/原理"、长句多 → 逻辑版报告。
- 结果型信号：短句、行动词汇多、问"怎么办/该不该" → 结果版报告。
- 默认逻辑版；MVP 由显式按钮兜底。

## 7. 反馈回写规则（闭环核心）

1. 有帮助 + 评论提到某主题 → 该主题 weight +0.2、极性向评论情绪微调。
2. 没帮助 → 记录原因；连续 2 次没帮助 → 报告生成 Prompt 自动附加"上两次反馈认为 X 类建议无效，换一种路径类型"。
3. 每次回写都写入 feedbackLog，报告第 1 段可引用（"你上次提到……"）。

## 8. 给 Kimi 的前端生成清单（摘用）

> 生成时按页拆开喂，一次一页，附本节对应的组件表。

1. **采集页**：Next.js 页面，深色主题，组件见表 2.1，情绪词点选用 chip 按钮组。
2. **星图页**：优先 `three` + `@react-three/fiber`，固定透视相机 30° 俯角、拖拽旋转、滚轮缩放；粒子用发光球体（MeshStandardMaterial + emissive），连线用 Line，六域分区用 6 个淡色 Sprite 光环；点击粒子 → 右侧抽屉详情卡。**若 Kimi 无法产出可运行的 Three 代码，降级为 SVG 平面图（粒子=circle，发光=SVG filter，旋转=CSS transform）。**
3. **报告页**：五段卡片式布局 + 逻辑版/结果版切换 + 反馈组件，深色主题与星图页统一。
4. 全局：深空配色（背景 `#0a0e1a`，主色金 `#f5c76a`，负向蓝紫 `#7b8cff`，正向橙 `#ff9a5c`）、中文 UI、移动端优先。
