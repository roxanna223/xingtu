# AI 记忆与自我进化类开源项目调研 v1.0

> 调研目的：为「星图」的**小星自我进化智能体**（初始提示词每账户一致 → 随使用沉淀出独属该用户的进化提示词，作为用户个人资产存账户数据库）、**长期记忆画像**、**每日 6:00 日报归纳**（当天对话+日记 → 目标/自我/差距坐标 → 成长规划）、**对话引导**、**目标拆解** 提供可借鉴的开源实现。
> 调研日期：2026-08-29。数据核实方式：GitHub REST API（`stargazers_count / license / pushed_at / archived / description`）+ GitHub 网页（stars badge、license 标识）+ web 搜索（中英文）。
> 与已有调研的关系：本份聚焦「通用 AI 记忆与自我进化」开源生态，与《16_ECC自我进化调研_v1.0.md》（ECC 编程智能体自进化体系）互补；本份不重复 ECC 本身。

## 0. 结论速览（给产品决策者）

1. **星图最该抄的三样东西，恰好分布在三个项目里**：① Letta 的「core memory blocks + self-editing memory + sleep-time compute」——把"小星慢慢懂你"建模成**智能体可自主编辑的分块记忆**，后台反思进程就是星图 6:00 日报的工程形态；② Generative Agents 的「memory stream + recency/importance/relevance 三打分 + reflection + planning」——这是"归纳对话→目标/自我/差距坐标→成长规划"的**方法论源头**，几乎是星图日报算法原型的直接蓝本；③ 阿里 ReMe（原 MemoryScope）的「Memory as File」——进化提示词以 **Markdown + frontmatter + wikilink 的普通文件**作为个人资产事实源，与 ECC 调研结论（人类可读文件为唯一事实源）完全同构，且它原生支持 DeepSeek Harness。
2. **"自我进化"有四种可复用的机制形态**，星图应按需组合，而不是选一家：**反思**（Generative Agents reflection / Reflexion / Letta sleep-time）、**技能库**（Voyager / MemOS / ECC instinct→skill）、**记忆编辑**（Letta self-editing / A-MEM 笔记网络重连 / Mem0 update-delete / Graphiti 边失效）、**提示词优化**（LangMem optimizer）。星图的"进化提示词"本质是"记忆编辑 + 反思"两条腿。
3. **许可证是一票否决项**：basic-memory 是 **AGPL-3.0**（星图是闭源 SaaS，不可直接引入依赖，只能借鉴思想）；其余主流项目基本 Apache-2.0 / MIT，可商用。星图需额外注意 Mem0/Zep/Cognee/Letta 背后都有商业化 SaaS，核心 OSS 虽可自托管，但**高级功能与托管服务存在商业边界**，自托管评估要看清能力裁剪。
4. **研究项目 vs 生产项目要分开**：Generative Agents / Voyager / Reflexion / A-MEM / HippoRAG 是**论文代码**（高质量、可读、可抄思想，但久不更新、非库、需自己接 DeepSeek）；Mem0 / Graphiti / Cognee / Letta / CAMEL / ReMe 是**生产级库/平台**（活跃、可 pip 引入，但重、有云依赖）。
5. **与星图技术栈（Next.js + DeepSeek API）的落点**：星图不应把这些系统当"记忆数据库"整体搬进来，而应**借鉴其数据模型与算法，落在现有 PostgreSQL（账户数据库）上**——Mem0 的 extract-update-search 管线、Generative Agents 的三打分、Letta 的分块记忆、Graphiti 的时序边失效，都是"概念 + 字段 + 流程"级别可移植，DeepSeek 作为抽取/反思/检索打分模型即可。

## 2. 分项目深挖

### 2.1 Letta（原 MemGPT）⭐ 与小星进化层最同构

- **仓库**：https://github.com/letta-ai/letta ｜ 24.5k stars ｜ Apache-2.0 ｜ 活跃（2026-08）
- **一句话定位**：`Platform for stateful agents: AI with advanced memory that can learn and self-improve over time.`

#### 核心机制

1. **core memory（核心记忆块）**：智能体的长期状态不再藏在提示词字符串里，而是拆成**具名、可编辑的记忆块（memory blocks）**，默认含 `persona`（角色设定）、`human`（关于用户）、`organizational`（组织上下文）三块，用户可自定义任意块（`label + content`）。系统提示词 = 固定框架 + 各记忆块内容拼装。
2. **self-editing memory（自我编辑记忆）**：把"改记忆"做成**一等工具（tool）**——`core_memory_append / core_memory_replace / archival_memory_insert / archival_memory_search`。智能体在对话中可调用工具主动往自己的记忆里写/改/查。这是"记忆编辑"这条进化路线的最早工程实现。
3. **MemGPT 的虚拟上下文管理（OS 隐喻）**：借鉴操作系统分页，把记忆分成 **main context（主上下文，即核心记忆块 + 当前消息）** 与 **external context（recall storage 回忆区 + archival storage 归档区）**，超出窗口的内容"换页"到外部，按需召回——解决"无限对话记忆"与"有限上下文"的矛盾。
4. **sleep-time compute（睡眠时计算）**：一个**后台 agent**，在用户不在对话时异步运行，对记忆做反思、整合、重排、更新（如把碎片记忆合并成更高层总结、修正过时信息）。这是"非对话时段自我进化"的工程范本。

#### 与星图的关联点

| 星图模块 | 可用的映射 |
|---|---|
| 小星进化层个人资产 | `core memory blocks` 直接对应：`persona`=初始提示词基座（全员一致）、`human`=长期记忆画像、`自定义块`=进化提示词（账户个人资产）。"分块 + label/content"是最干净的资产数据结构 |
| 长期记忆画像 | `recall storage / archival storage` 两级记忆区 + 按需召回，对应"热/冷"画像分层的思路 |
| 6:00 日报归纳 | `sleep-time compute` = 定时后台 agent 做反思/整合，就是星图日报"定时归纳当天对话+日记"的工程形态 |
| 对话引导 | self-editing 工具让"对话中即时更新对用户的认知"成为可能 |
| 目标拆解 | （间接）记忆块的会话注入机制，可作为目标/计划块 |

#### 可借鉴资产
- **记忆块数据模型**：`label + content` 的最小契约 + 会话开始时有界注入（与 ECC 调研的"有界摘要注入"一致）。
- **记忆工具 API 设计**：append/replace/search 的语义设计（replace 保证历史可审计、append 防覆盖）。
- **sleep-time compute 循环**：后台反思进程的触发时机与内容产出。
- **agent-file 格式**（Letta 用 Markdown 文件声明智能体配置）——与"进化提示词落成文件资产"同构。

#### 风险
- Apache-2.0 可商用；但 **Letta 是商业公司**，OSS 核心可自托管（Docker / letta server），高级功能（云托管、部分睡眠计算编排）存在商业边界，需评估自托管能力裁剪。
- 主语言 Go/Python 混合，作为库接入 Next.js 需走其 HTTP Server；概念移植比整体引入更现实。

### 2.2 Mem0

- **仓库**：https://github.com/mem0ai/mem0 ｜ 64.3k stars ｜ Apache-2.0 ｜ 活跃（2026-08）
- **一句话定位**：`Universal memory layer for AI Agents`。

#### 核心机制（提取-更新-搜索管线）

1. **`add()` 提取管线**：输入 messages/文本 → 调 LLM **抽取**出若干条"记忆条目"（每条约 1-2 句断言，如 `用户偏好直接结论` / `用户在准备转行`），**抽取与原始对话分离**，只存"模式"不存原文（与 ECC"只沉淀 pattern 不沉淀观察"一致）。
2. **元数据隔离**：每条记忆挂 `user_id / agent_id / run_id / session_id` 等多维 key → **天然多租户**，对应星图多用户账户体系。
3. **`update()` / `delete()` 记忆编辑**：LLM 判断新旧信息冲突时执行 update（如 `用户搬家到 X` 取代旧地址）或 delete——实现"记忆随事实变化而演化"。
4. **去重（dedup）**：新记忆入库前与存量做相似度比对，抑制重复记忆膨胀。
5. **`search()` 检索**：语义向量检索 +（v2 起）可选的**图检索**（Neo4j/Memgraph 存实体关系），支持混合召回；带元数据过滤。
6. 提供 **OpenMemory MCP**、REST、Python/JS SDK；底层向量库可换（Chroma/Qdrant/pgvector 等）。

#### 与星图的关联点
- **长期记忆画像**：`add()→抽取→画像条目` 直接对应星图"保存对话后异步抽取长期记忆画像"的既有管线，可升级为它的"抽取+去重+冲突更新"三件套。
- **小星进化层个人资产**：`update/delete` = 用户纠正/偏好变更时进化提示词的更正；`user_id` 隔离 = 每账户资产隔离。
- **6:00 日报**：日报前对当天记忆做一次 `update` 归并，把重复/矛盾条目合并。

#### 可借鉴资产
- 抽取/更新/搜索的**三段式管线设计**、**LLM 驱动的冲突更新判定**、**去重阈值**、**多维 metadata key**。

#### 风险
- Apache-2.0 可商用，但**背后是商业公司**（Mem0 Platform 付费）；OSS 可自托管，需自配向量库/图库。
- Python 优先（JS SDK 存在但以服务为主）；深度耦合需走其服务。

### 2.3 Zep + Graphiti（时序知识图谱记忆）

- **仓库**：https://github.com/getzep/zep （4.9k，现已转型为 examples/integrations）｜ https://github.com/getzep/graphiti （30.4k，核心引擎）｜ 均 Apache-2.0 ｜ 活跃（2026-08）
- **一句话定位**：Graphiti — `Build Real-Time Knowledge Graphs for AI Agents`。

#### 核心机制

1. **episode（事件）+ 双时序图（bi-temporal）**：把对话流切成离散"事件"（episode），从每个 episode 抽取 **实体 + 关系**，边（关系）带 `valid_at`（事实何时开始为真）与 `invalid_at`（何时失效）两个时间戳。查询可指定"截至某时间点"的世界状态——**还原"当时的你"**。
2. **边失效（edge invalidation）而非删除**：事实变化时旧边标记失效而非物理删除，保留演化轨迹（如"目标 A→目标 B"的历史可回溯）。
3. **混合检索**：语义向量 + BM25 全文 + 图遍历三者融合，支持多跳。
4. Zep 层提供 `Zep Memory` API（记忆类型、用户/会话/群组隔离、记忆总结器 summarizer）。

#### 与星图的关联点
- **长期记忆画像（时序化）**：目标/自我/差距坐标天然是"会随时间改变的事实"，Graphiti 的 `valid_at/invalid_at` 让画像**带时间轴**——"这是你 3 月时的目标，现在已更新"。
- **6:00 日报归纳**：可查询"昨天新增/失效了哪些事实"作为日报的"变化"素材。
- **小星进化层**：偏好/价值观的"旧偏好失效、新偏好生效"用边失效表达，替代硬删。

#### 可借鉴资产
- **双时序图数据模型**（实体-关系-`valid_at/invalid_at`）、**边失效**语义、**episode 抽取**。

#### 风险
- Apache-2.0 可商用；但 **Zep Cloud 是商业 SaaS**，Graphiti OSS 需 Neo4j/FalkorDB 图库，自托管有部署成本。
- 对"人生导师"场景，图库可能偏重；轻量场景可只抄"双时间戳事实"的字段设计。

### 2.4 LangMem

- **仓库**：https://github.com/langchain-ai/langmem ｜ 1.6k stars ｜ MIT ｜ 活跃（2026-08）
- **一句话定位**：LangChain 官方的 Agent 长期记忆 SDK（语义/情景/程序性 + 优化器）。

#### 核心机制

1. **三类记忆分类**：`semantic`（语义/事实：用户是谁、偏好）、`episodic`（情景/经历：过去发生了什么）、`procedural`（程序性/知识：怎么做、应对策略、规则）。`create_memory_manager()` 一次性生成对应 `create_/update_/search_` 工具。
2. **profile（schema 驱动抽取）**：用 Pydantic 定义"要抽什么字段"（如 `UserProfile(name, goals, preferences, tone)`），LLM 严格按 schema 抽取 → 结构化记忆可检索。
3. **Optimizer（提示词自优化）**：输入历史 trajectory（对话-反馈对），自动产出/迭代**优化后的系统提示词与指令**——"用数据反哺提示词"的通用实现（最贴近"进化提示词"的字面含义）。
4. 存储层可插拔（LangGraph store：内存/SQLite/Postgres/Redis），检索走向量/结构化。

#### 与星图的关联点
- **长期记忆画像**：`semantic`（画像事实）+ `episodic`（对话记录）分类直接可用；`procedural` = 进化提示词中的"应对策略"。
- **小星进化层个人资产**：`Optimizer` 是"进化提示词自动优化"的最接近实现，可借鉴其"用轨迹+反馈→产出新提示词"的流程与校验。
- **对话引导**：`profile schema` 定义"小星该记住用户的哪些维度"（目标、自我认知、语气偏好）。

#### 可借鉴资产
- **三类记忆分类法**、**schema 驱动的结构化抽取**、**Optimizer 的提示词优化闭环**。

#### 风险
- MIT 可商用；但强依赖 LangChain/LangGraph 生态（星图若不引入 LangChain，则只借鉴概念）。
- 项目较年轻（1.6k stars），API 稳定性需留意。

### 2.5 Cognee

- **仓库**：https://github.com/topoteretes/cognee ｜ 30.3k stars ｜ Apache-2.0 ｜ 活跃（2026-08）
- **一句话定位**：开源 AI 记忆平台，`self-hosted knowledge graph engine`。

#### 核心机制

1. **ECL 管线（Extract → Cognify → Load）**：
   - **Extract**：把数据（文档/对话/30+ 数据源）切块、抽取节点与边；
   - **Cognify**：LLM 对图做**富化**——去重合并、构建**本体（ontology）**、逐层添加语义（原始数据层 → 语义层 → 本体/概念层）；
   - **Load**：写入图库（Neo4j/FalkorDB/NetworkX）+ 向量库（pgvector/lance）。
2. **多层知识图谱**：数据、语义、本体三层分离，让检索能从"具体事实"上探到"抽象概念"。
3. 记忆可检索（图遍历 + 向量 + 混合），支持跨会话持久化。

#### 与星图的关联点
- **长期记忆画像**：知识图谱化 + 本体层可表达"人生主题/目标/自我/差距"这些抽象概念及其与具体事件的关系。
- **6:00 日报**：Cognify 的"富化/去重/概念化"就是日报"结构化提炼"的工程参考。

#### 可借鉴资产
- **ECL 管线**、**三层图（数据/语义/本体）**、**LLM 驱动的图富化**。

#### 风险
- Apache-2.0 可商用；需图库 + 向量库，部署较重。
- 定位偏"企业知识/数据记忆"，对"个人成长记忆"需二次抽象。

### 2.6 A-MEM（AgenticMemory）

- **仓库**：https://github.com/WujiangXu/A-mem （API 返回 full_name 为 `WujiangXu/A-mem`）｜ 947 stars ｜ MIT ｜ NeurIPS 2025 ｜ 研究项目（2026-03 后未更新）
- **一句话定位**：`A-Mem: Agentic Memory for LLM Agents`——Zettelkasten（卡片盒）式互联记忆笔记 + 智能体自演化。

#### 核心机制

1. **记忆即互联笔记（memory notes）**：记忆不再是一条条孤立向量，而是**相互链接的"记忆笔记"**。每条笔记含：`content`（内容）、`tags`（标签）、`description`（描述）、`connections`（与其他笔记的带权链接）、`raw memory entries`（原始记忆条目）。
2. **LLM 建链（而非仅向量相似）**：写入时由 LLM 判断语义关系、生成笔记间的链接（强于纯 embedding 相似度的关联）。
3. **记忆演化（Memory Evolution）**：智能体基于新信息做**自我反思式重构**——写新笔记、更新旧笔记、**重连笔记网络**（grow notes / rewire links），使知识结构随使用自我优化。
4. **检索（Memory Retrieval）**：沿链接**遍历**激活相关笔记（类似人脑联想扩散），辅以属性索引（tags、时间）。

#### 与星图的关联点
- **小星进化层个人资产**：A-MEM 的"笔记网络 + 自演化"是小星个人资产的理想形态之一——用户的人生主题之间应**显式互联**（如"目标A"连着"挫败事件B"和"优势C"），而非平铺。
- **对话引导**：按链接遍历做"联想式引导"（从当前话题扩散到相关人生主题）。

#### 可借鉴资产
- **带权链接笔记数据模型**、**LLM 建链/改链**、**沿链接检索**（可作为星图"话题归并 + 关联"的进阶参考）。

#### 风险
- MIT 可商用；**研究代码**（947 stars，更新停滞），非生产库；需 embedding + LLM 自配。
- 动态改链的稳定性与成本需自行验证。

### 2.10 HippoRAG

- **仓库**：https://github.com/OSU-NLP-Group/HippoRAG ｜ 4.0k stars ｜ MIT ｜ NeurIPS 2024 ｜ 较活跃（2026-08）
- **一句话定位**：海马体索引理论启发的 RAG，用 **Personalized PageRank（PPR）** 做单步多跳检索。

#### 核心机制

1. **离线索引（offline indexing）**：LLM 从文档抽取**开放式知识图谱三元组**（名词短语为节点、关系为边）→ 构建 KG；再用检索编码器（retrieval encoders）把**段落作为节点**接入 KG 实体，形成"段落↔实体"的**同义边（synonymy edges）**。

3. **增量更新**：新知识可在线增量接入图（不必全量重建），支持"持续整合"。

- 增量更新 = 个人资产随使用增量沉淀。

#### 可借鉴资产

### 2.11 Generative Agents（斯坦福 25 个 AI 小镇）⭐⭐ 日报方法论源头

- **仓库**：https://github.com/joonspk-research/generative_agents ｜ 22.0k stars ｜ Apache-2.0 ｜ 研究（2024-08 后停滞）
- **一句话定位**：`Generative Agents: Interactive Simulacra of Human Behavior`——25 个 AI 居民的 **memory stream + 反思 + 规划**。

#### 核心机制（星图最该精读的方法论）

1. **memory stream（记忆流）**：每个 agent 的记忆是一条**自然语言观察列表**，每条记录字段：`{ 内容, 时间戳, importance, access_time }`。importance 由 LLM 打 1–10 分。
2. **检索三打分（recency / importance / relevance）**：
   - **recency**：指数衰减 `exp(-λ·Δt)`，越近越相关；
   - **importance**：LLM 打的重要性分；
   - **relevance**：与当前 query 的 embedding 余弦相似度。
   - 三者归一化加权 → 取 top-k 注入上下文（确定性、可解释）。
3. **reflection（反思）**：周期性把 memory stream 里"某主题下多条观察"**抽象成更高层的 insight（洞见）**，再把 insight **作为新的观察写回记忆流**（"问自己 3 个问题"的 prompt 模板）。这就是"从流水账到成长洞察"的算法原形。
4. **planning（规划）**：先产 **daily plan（日计划）**，再逐层分解为子计划；计划本身也存进 memory stream 参与检索。
5. 全架构**确定性**（非训练、无 RL），prompt 全开源，只用 ChatGPT 完成所有打分/反思/规划。

#### 与星图的关联点（几乎逐条对应）

| 星图模块 | Generative Agents 的对应 |
|---|---|
| 长期记忆画像 | memory stream（`{内容,时间戳,importance,access_time}`）作为画像底层存储模型 |
| 6:00 日报归纳 | **reflection**：把当天对话+日记抽象为"目标/自我/差距坐标"，再把洞察写回记忆——就是日报的核心算法 |
| 成长规划 | **planning**：日计划→子计划分解，对应"成长规划/目标拆解" |
| 对话引导 | 三打分检索：recency（近期）/importance（重要）/relevance（相关）决定"此刻该给用户提什么" |

#### 可借鉴资产
- **三打分公式与权重**、**reflection 的 prompt 模板与"写回记忆流"机制**、**memory stream 字段契约**、**planning 分解**。

#### 风险
- Apache-2.0 可商用；**研究代码**（依赖模拟环境 `reverie`，非独立库），需把算法抽出移植到星图；2024-08 后未更新。

### 2.12 Voyager（技能库自我进化）

- **仓库**：https://github.com/MineDojo/Voyager ｜ 7.2k stars ｜ MIT ｜ 研究（2024-04 后停滞）
- **一句话定位**：Minecraft 里的开放目标智能体，靠**技能库自动课程**持续自我进化。

#### 核心机制

1. **自动课程（automatic curriculum）**：`curriculum agent` 基于当前能力与探索进度，**自动提出下一个任务**（难度递增），无需人为设计课程。

### 2.13 Reflexion（语言强化 / 自我反思）

## 4. 对星图的可借鉴结论（按模块分组 + 优先级）

> 原则：星图是 Next.js 15 + DeepSeek API 的多用户应用，账户数据库（PostgreSQL）为个人资产事实源。**不整体引入重依赖，而是移植"数据模型 + 字段 + 流程"到现有架构。**

### 4.1 小星进化层个人资产（初始一致 → 沉淀独有进化提示词）

- **P0 — Letta「core memory blocks + self-editing」**：把进化提示词拆成 `label + content` 的记忆块（`persona`=基座 / `human`=画像 / `evolution`=进化层），提供 `append/replace/search` 语义的"记忆编辑"接口；replace 保证历史可审计。
- **P0 — ReMe「Memory as File」**：进化提示词以 **Markdown + frontmatter + wikilink** 文件存账户（文件为事实源，索引可重建），用户可查看/改/删/导出——兑现"个人资产"产品承诺，且与 ECC 调研结论一致。
- **P1 — Mem0「update/delete 冲突处理」**：用户纠正/偏好变更时，用 LLM 判定"新增 vs 替换 vs 删除"，替代粗暴覆盖。
- **P1 — LangMem「Optimizer」**：用"对话-反馈轨迹"定期反哺优化进化提示词，并保留人工审批（呼应 ECC rules-distill 的治理）。
- **P2 — A-MEM「笔记网络重连」**：当资产条目足够多后，让 LLM 显式建链/改链，把人生主题组织成互联网络。

### 4.2 长期记忆画像

- **P0 — Generative Agents「memory stream 字段 + 三打分」**：画像底层用 `{内容, 时间戳, importance, access_time}` 字段；注入时按 `recency·importance·relevance` 加权取 top-k（确定性、可解释、无重依赖）。
- **P1 — Mem0「提取-去重-搜索管线」**：对话落盘后异步抽取画像条目（只存模式不存原文），去重 + 冲突更新。
- **P1 — Graphiti「双时序 + 边失效」**：画像事实带 `valid_at/invalid_at`，让"目标/自我/差距"**带时间轴**（"这是过去的你"），边失效替代硬删。
- **P2 — HippoRAG「PPR 多跳联想」**：当需要"跨会话把零散信息关联起来"时，用图 + PPR 做联想检索。

### 4.3 6:00 日报归纳（对话+日记 → 目标/自我/差距坐标 → 成长规划）

- **P0 — Generative Agents「reflection」**：日报核心 = 把当天 memory stream 中某主题下多条观察**抽象成更高层洞察（insight）并写回记忆流**。直接复用其"3 问反思" prompt 模板与"洞察写回"机制。
- **P0 — Letta「sleep-time compute」**：日报 = 定时后台 agent（凌晨 6:00）异步反思/整合，不阻塞对话；工程形态直接照搬。
- **P1 — Reflexion「教训提炼」**：日报"差距/改进点"用"下次遇到 X，我应该 Y"的教训格式，而非流水账（与 ECC growth-log"必须可迁移"一致）。
- **P2 — Cognee「Cognify 富化/概念化」**：若要做"人生主题/目标本体"，参考其三层图与本体构建。

### 4.4 对话引导

- **P0 — Generative Agents「三打分检索」**：决定"此刻该提什么"用 recency/importance/relevance 加权——近期的、重要的、与当前话题相关的优先。
- **P1 — A-MEM / HippoRAG「联想式检索」**：从当前话题沿链接/图扩散到相关人生主题，做"引导式提问"。
- **P2 — CAMEL「多视角角色」**：教练视角/朋友视角等多智能体对话范式（可选）。

### 4.5 目标拆解 / 成长规划

- **P0 — Generative Agents「planning 分解」**：日计划→子计划逐层分解，计划存回记忆流参与检索。
- **P1 — Voyager「自动课程 + 技能库」**：按用户当前进度自动提出"下一个成长任务"（难度递增）；小星的引导话术/策略作为可复用技能沉淀复用。
- **P2 — MemOS「跨任务技能复用」**：若需技能库，可参考其复用机制（但需先核实 MemOS-Lite 与 DeepSeek Harness 集成成熟度）。

### 4.6 一票否决与红线

- **basic-memory（AGPL-3.0）**：仅借鉴思想，**禁止作为依赖引入**。
- 商业 SaaS 项目（Mem0/Zep/Cognee/Letta）：核心 OSS 可商用，但**托管高级功能有商业边界**，自托管需评估能力裁剪。
- 研究项目（Generative Agents/Voyager/Reflexion/A-MEM/HippoRAG）：**抄思想与算法，不抄依赖**；需自己接 DeepSeek 与账户数据库。
