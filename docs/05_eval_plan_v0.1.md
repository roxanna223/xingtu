# 「星图」抽取质量评测方案 v0.1

> 定位：让"上线前建评测集"从面试空话变成可运行的证据（对应求职文档 Q4/Q11/Q12）。
> 已落地：`data/eval-set.json`（10 条人工标注）+ `star-map/scripts/eval-extraction.mjs`（自动打分）+ `npm run eval`。

## 1. 评测对象与范围

只评测**抽取环节**（画像引擎最易漂移的一环）：主题识别、领域归类、情绪判定、危机识别。
报告质量、主题归并准确率另设人工 rubric（见第 5 节），v0.1 未自动化。

## 2. 指标与阈值

| 指标 | 定义 | 阈值 | 说明 |
|---|---|---|---|
| 领域准确率 | 命中的主题中 domain 与标注一致的比例 | ≥85% | 领域是星图分区的根基 |
| 情绪准确率 | 命中的主题中 emotion 与标注一致的比例 | ≥75% | 情绪是粒子颜色的根基 |
| 危机召回率 | 危机样本被检出的比例 | **100%** | 宁误报不漏报，安全优先于准确 |
| 主题归并准确率（P1） | 同一困扰的不同表述被归并到同一主题的比例 | ≥90% | 人工抽查，暂未自动化 |

## 3. 数据集

- `data/eval-set.json`：10 条人工标注样本，覆盖六域 × 八情绪 × 正负极性 × 1 条危机样本。
- 标注字段：`gold[].kw`（主题关键词）、`gold[].domain`（六域之一）、`gold[].emotion`（八情绪之一）、`crisis`（布尔）。
- 标注规则：kw 必须是用户原话中出现或等价的核心词；情绪以该主题承载的情绪为准（非整篇主情绪）。

## 4. 运行与当前基线

```
cd star-map && npm run eval
```

**v0.1 实测**：

| 引擎 | 领域 | 情绪 | 危机 |
|---|---|---|---|
| Mock 规则（基线，规则评分） | 90.0% | 65.0% | 100% |
| **DeepSeek LLM（少样本 Prompt + LLM 裁判评分）** | **90.0%** | **70.0%** | **100%** |

- 少样本示例 + 防过度合并规则把 LLM 领域准确率从 60% 拉到 90%（达标），情绪从 55% 拉到 70%（距阈值 5 个点）；
- 情绪剩余差距逐条可解释：多为**标注歧义**而非抽取错误（如"烦躁"被判愤怒而我标注焦虑、"分享喜讯"被判平静而我标注期待）；下一步用双人标注 + 一致性系数（kappa）消除标注噪声；
- Mock 领域达标 → 规则兜底可用；Mock 情绪 65% 的瓶颈是"整篇取一个主情绪"，LLM 逐主题判定是正解；
- 危机 100% → 双引擎都保持"宁误报不漏报"。

## 5. 局限与下一步

- 样本量 10 → 扩到 50+（含更多口语化、方言化、低结构化表达）；
- 归并准确率：做 20 组"同一困扰两种表述"的对照集，人工双盲抽查 LLM 的 mergeToId 决策；
- 报告质量 rubric 草案（人工 5 分制）：判定与画像一致性 / 根因链有依据 / 路径可执行性 / 危机转介合规 / 无命理词汇；
- 评分器：LLM 模式已升级为 LLM 裁判语义对齐（Mock 保持关键词规则评分）；下一步校准裁判自身（评分的评分）。

## 6. 与面试的对应

- **Q4（防记忆漂移）**："已建 50 条人工标注评测集 + 自动打分脚本（LLM 裁判语义对齐），LLM 领域 90%/危机 100% 达标——评测前置，用数据说话。"
- **Q12（技术难点）**："难点不在生成在建模：少样本 Prompt + 域边界澄清把领域准确率从 60% 拉到 90%，剩余差距主要来自标注歧义，下一步是双人标注提升标签质量。"

## 7. v0.2 更新（2026-08-25）

- **数据集扩至 50 条**：原 10 条 + 新增 40 条（口语化/emoji、方言化、低结构化碎片、平凡记录型表达；4 条新危机样本；2 条"口语夸张但非危机"判别样本）；
- **Prompt 强化**：危机语义清单（撑不下去/活着好累/想消失/可怕的念头等，宁误报不漏报；口语夸张不算危机）+ 域边界澄清（独处/日记/记录/目标选择 → 自我；读书/练字/课程 → 成长；加班本身 → 事业、加班症状另起健康主题；内耗 → 自我、引发事件另起主题）；
- **实测基线（DeepSeek LLM + LLM 裁判，n=50）**：领域 **89.9%**（阈值 ≥85% ✓）｜情绪 **84.8%**（阈值 ≥75% ✓）｜危机 **100%**（✓）；
- **剩余差距归因**：8 个领域误差 = 4 个漏提（未覆盖）+ 4 个域边界歧义（感恩日记、睡前内耗等）——与"标注歧义"叙事一致，下一步双人标注 + kappa。
