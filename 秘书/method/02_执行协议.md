# 「秘书」方法层 02 · 执行协议（每一步的标准动作）

> 目的：让"锚定本质"变成肌肉动作，而不是靠自觉。执行者是谁不重要（人 / AI / 子代理），协议一样。
> 适用范围：秘书接入的**任何项目**的任何任务——代码、文档、设计、部署、运营，全部适用。
> 记号约定：下文「实例目录」= `projects/<项目名>/`；「锚点卡」= 实例目录下 `00_核心锚点.md` 第一节。
> 前置：实例目录不存在（项目未接入）→ 先按 `01_本质勘察法.md` + `06_接入手册.md` 接入，再执行。

## 一、开工（5 步）

1. **读锚点卡**：读当前实例目录的 `00_核心锚点.md` 第一节（一屏）。**哪怕读过一百遍。**
2. **写行为句**：把本次任务写成——`用户做了什么 → 得到什么 → 因此更可能发生什么`。
3. **过本质三问**：三问至少一问为"是"；全否 → 本任务定义有偏差，**停止**，记实例 `03_偏差日志.md`，重新定义任务。
4. **建记录**：在实例 `02_任务追踪器.md` 建本步记录：任务（行为句）/ 锚点（价值链环节）/ 三问预检 / 状态=进行中。
5. **对红线**：对照锚点卡红线与姿态条目，确认不踩线。

## 二、执行

- 只做与锚点一致的部分；多余的花活不做（**哪怕顺手**）。
- 执行中发现"做起来偏离锚点"：立即停下 → 记实例 `03` → 回读锚点卡 → 重写行为句 → 再继续。**不回退硬做。**

## 三、完工（5 步）

1. **写实际行为句**：实际发生了什么（只写行为，不写形容词）。
2. **核对**：实际行为句 vs 开工行为句，一致吗？
3. **偏差自检（四类）**：
   - **记忆偏差**：对初心/框架记错了（上下文衰减）——回读原文；
   - **判断偏差**：本质三问判错了——重判并记录理由；
   - **语言偏差**：被抽象名词包装骗了——把名词换成行为句再评；
   - **执行偏差**：做偏了/做多了——只改回锚点，不多做。
4. **记录**：有偏差 → 实例 `03_偏差日志.md` 记一条（现象/类型/原因/回锚动作/结果）；无偏差 → 追踪器标"锚点核对 ✅"。
5. **更新状态**：任务状态 + "下一步锚点"（下一步要抓的本质点是什么）。

## 四、铁律

1. 每一步开工前必读锚点卡——**上下文会衰减，文件不会**；
2. 追踪器的"锚点"列留空 = 该步未开工；
3. `00` 只能走提案流程修改，禁止执行任务时顺手改；
4. 追踪器与偏差日志**只追加**，不修改历史（写错就新增一条"更正"记录）；
5. 多项目并存时，先确认在哪个实例目录作业，**禁止跨项目混用锚点**。
