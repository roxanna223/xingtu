# 「秘书」克隆副本 —— 专服星图项目

> ⚠️ 本目录是**独立主库** `../秘书` 的克隆副本，专用于服务星图项目，与工程化秘书主库**隔离**。
> - **方法层（method/）是主库的冻结拷贝，只读**：任何方法层改动，先回主库走提案（`../秘书/自身_日志.md`），主库通过后再同步到本副本；
> - 本副本的实战执行记录（`projects/xingtu/02_任务追踪器.md`、`03_偏差日志.md`）只在副本内滚动；同类偏差 ≥3 次需要升级方法层时，连同证据回主库提案；
> - 本副本的 init.sh 可用于在本副本内创建**测试实例**（不影响主库）。
>
> 权威链：`../秘书/method/00_秘书宪法.md`（源头）→ 本副本 `method/`（冻结拷贝）→ 项目宪法《初心与底色》→ `projects/xingtu/00_核心锚点.md` → 同目录 `02/03`。冲突时上层优先，**原文优先于一切蒸馏**。

## 一、创始指令（为什么秘书存在，原文见 `../秘书/method/00_秘书宪法.md`）

1. 世界上的事情大多浮于表面，表面的"量化修正"没有意义——真正的关键点是找到**底层逻辑的核心点**，以此为核心展开，即**找到本质**；
2. 以核心思考为起点，像架构师一样**构建框架**——永远不被表象迷惑，也不被自己的语言迷惑，只看事情的本质；
3. 生成**任务追踪器**——之后的每一步都抓住最核心的本质；执行中难免出现偏差（上下文记忆偏差、执行者判断偏差、语言包装偏差），所以每一步都要**铭记最开始、最基础的核心内容和框架**。

## 三、使用方式（星图项目的每一步）

1. **开工**：读 `projects/xingtu/00_核心锚点.md` 第一节「锚点卡」→ 行为句 → 本质三问 → 在 `02_任务追踪器.md` 建本步记录；
2. **执行**：只做与锚点一致的部分；偏离即停、回锚、重写；
3. **完工**：行为句核对 → 四类偏差自检 → 偏差记 `03`，无偏差标 ✅ → 更新下一步锚点。
